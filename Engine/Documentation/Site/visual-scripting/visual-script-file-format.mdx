A visual class is saved as one `.vscript` file. The file is text [MDF](/docs/api/mdf/), the engine's own data format, so it diffs and merges like source code. This page describes the schema so you can read a class in a code review, fix a merge conflict, or generate a class from a tool.

## A real file

This is `BP_Door.vscript` from the engine's test project, trimmed to one of its three functions and the first four nodes of its event graph <Source path="Engine/Source/Developer/MowoTestKit/Fixtures/TestProject/Content/BP_Door.vscript" />:

```mdf title="Content/BP_Door.vscript"
Package "VisualScriptClass" {
    id: uuid("8DBFCACB-C269-F3DB")
    format_version: 1
}

VisualScriptClass {
    schema: 4
    class: "BP_Door"
    parent: "AActor"

    Variable {
        name: "IsOpen"
        vtype: "Bool"
        val: false
    }
    Variable {
        name: "OpenSpeed"
        vtype: "Float"
        val: 1.5
    }
    Variable {
        name: "TriggerRadius"
        vtype: "Float"
        val: 250.0
    }
    Function {
        name: "OpenDoor"
        ret: "Void"
        entry: 0

        Param {
            name: "Speed"
            vtype: "Float"
        }
        Node {
            kind: "Event"
            name: "OpenDoor"
            execNext: 2
        }
        Node {
            kind: "Return"
            execNext: -1
        }
        Node {
            kind: "SetVar"
            var: "IsOpen"
            execNext: 1

            Input {
                link: -1
                pin: 0
                vtype: "Bool"
                val: true
            }
        }
    }
    Graph {
        event: "OnInteract"
        entry: 0

        Node {
            kind: "Event"
            name: "OnInteract"
            execNext: 1
            x: 40.0
            y: 60.0
        }
        Node {
            kind: "Branch"
            execNext: 4
            execElse: 6
            x: 280.0
            y: 60.0

            Input {
                link: 2
                pin: 0
            }
        }
        Node {
            kind: "CallGraphFunction"
            function: "IsPlayerInRange"
            execNext: -1
            x: 110.0
            y: 240.0

            Input {
                link: 3
                pin: 0
            }
        }
        Node {
            kind: "GetVar"
            var: "TriggerRadius"
            execNext: -1
            x: 40.0
            y: 400.0
        }
    }
}
```

A file that has been through the asset package migration starts with a small `Package "VisualScriptClass"` block carrying the asset id, as `BP_Door.vscript` does; the loader skips it and the class follows. Files without it load the same way.

Read the event graph like this: node 0 is the entry. Its `execNext: 1` runs the Branch. The Branch's condition input is linked to node 2's output, a pure call to `IsPlayerInRange`, whose argument is linked to node 3, a read of `TriggerRadius`. The Branch continues at node 4 when true and node 6 when false.

## The class block

The root node is `VisualScriptClass`. The serializer writes its parts in a fixed order <Source path="Engine/Source/Runtime/VisualScripting/Private/VisualScriptGraphSerializer.cpp" />:

| Key or child | Meaning |
| --- | --- |
| `schema` | The schema version the file was written with. |
| `class` | The class name. |
| `parent` | The parent class, native or visual. |
| `Variable` | A class variable: `name`, `vtype`, `val`, plus `replicated`, `repNotify`, `editable`, `exposeOnSpawn` when set. |
| `Function` | `name`, `ret`, `pure`, `rpc` (RPC flag bits), then `Param` and `Local` children and the graph body. |
| `Macro` | `name`, `In` and `Out` pin children (`name`, `exec`, `vtype`), then the graph body. |
| `Dispatcher` | `name`, `Param` children, and `Handler` children with an `fn` function name. |
| `Interface` | `name` of an implemented interface. |
| `Component` | A slot: `name`, `type`, optional `loc`, `rot`, `scale`, `attach`, and `Default` children with `prop` plus a constant. |
| `Graph` | An event graph: `event` plus the graph body. |

A **graph body** is `entry`, the index of the entry node, followed by `Node` children. Functions and macros use the same body, written by the same helper.

## Nodes

Each `Node` writes its `kind` as a string and only the keys it uses <Source path="Engine/Source/Runtime/VisualScripting/Private/VisualScriptGraphSerializer.cpp" />:

| Key | Meaning |
| --- | --- |
| `kind` | The node kind, for example `Branch` or `CallFunction`. See [Flow control](/docs/visual-scripting/flow-control/). |
| `name` | Event name, comment text, or another label. |
| `function` | Called function, macro or async action name. |
| `op` | The math operation of a `Pure` node, as an integer index into `VisualScriptPureOp`. |
| `var` | Variable, property, gate, dispatcher, pin or class name, depending on the kind. |
| `ns`, `key`, `src` | Localization namespace, key and source text of a `MakeText` node. |
| `execNext`, `execElse` | The next node on the first and second exec outputs. `-1` means none. |
| `execNextPin`, `execElsePin` | Which exec input of the target node to enter, for macros with several exec inputs. |
| `id` | The node's stable id. Diff and merge pair nodes by it, so deleting a node does not renumber the others. |
| `bp` | `true` when the node has a breakpoint. |
| `bpCond`, `bpLog` | The breakpoint's condition and logpoint message. |
| `x`, `y`, `w`, `h` | Canvas position, and a comment's size. |

Children of a node:

- `Input`: one per input pin. `link` is the source node index, or `-1` for a constant. `pin` is the source output pin. A constant also writes a value.
- `Exec`: one per list output, as on Sequence, Switch or Multi Gate, with `to` and an optional `pin`.
- `Timeline`: `length`, `loop`, and `Track` children with `name`, `type` and `Key` children (`t`, `v`, `vec`, `interp`).

## Constants

A constant writes `vtype` and `val` <Source path="Engine/Source/Runtime/VisualScripting/Private/VisualScriptGraphSerializer.cpp" />. Vectors use MDF's vector literal, as in `val: vec3(0.0, 1.0, -8.0)`.

- **Object constants** never store a pointer. They write `objref` as `Self`, `Name` or `Tag`, and `ref` with the name or tag. The reference resolves against the world when the graph runs.
- **Containers** add `ctype` (`Array`, `Map` or `Set`). Arrays and sets nest `Item` children. Maps add `ktype` and nest `Entry` children with a `Key` and a `Value`. Containers nest, so an array of arrays round-trips.

```mdf title="An array constant on an input pin"
Input {
    link: -1
    pin: 0
    vtype: "Int"
    ctype: "Array"

    Item {
        vtype: "Int"
        val: 2
    }
    Item {
        vtype: "Int"
        val: 4
    }
}
```

<Callout type="note">

The loader recognizes the type names `Bool`, `Int`, `UInt32`, `Int64`, `UInt64`, `Float`, `Double`, `Vec3`, `String` and `Object`. Other names, such as `Vec2`, `Vec4` and `Quat`, read back as `Void` <Source path="Engine/Source/Runtime/VisualScripting/Private/VisualScriptGraphSerializer.cpp" />.

</Callout>

## Versioning

The current schema is **9** <Source symbol="VisualScriptGraph" />. A new field is only ever added, and only written when it differs from its default. So a file that uses no newer feature looks the same as it did before, and `BP_Door.vscript` above still says `schema: 4`.

| Version | Added |
| --- | --- |
| 1 | The original graph schema |
| 2 | Object references, macros, multiple exec inputs |
| 3 | Multi-track Timelines and async-action nodes |
| 4 | Node canvas positions and comment sizes |
| 5 | `HasAuthority` and `SwitchHasAuthority` |
| 6 | Replicated variables, component slot placement, `ClassRef` |
| 7 | Instance Editable and Expose on Spawn |
| 8 | RepNotify |
| 9 | `MakeText` and its `ns`, `key`, `src` properties |

<Callout type="warning">

A file written by a newer engine is **refused**, not loaded best-effort <Source path="Engine/Source/Runtime/VisualScripting/Private/VisualScriptGraphSerializer.cpp" />. An older build would drop what it does not understand, and the editor saves a graph back over its file, so loading it anyway would erase those nodes. Older files always load: missing fields take their defaults.

</Callout>

## Tools and cooking

`VisualScriptGraphSerializer` saves and loads both forms: a bare graph (root `VisualScriptGraph`) and a whole class (root `VisualScriptClass`), to a string or a file <Source symbol="VisualScriptGraphSerializer" />. Saving goes through a temporary file and a rename, so a crash mid-write cannot leave an empty `.vscript`. A file that already carries a package block keeps it when saved again. Git treats `.vscript` as text with its own `merge=vscript` driver <Source path="Engine/Source/Runtime/Core/Private/FileTypes.cpp" />.

When you cook, `.vscript` files are converted to binary MDF (mdfb) like the other game data types <Source path="Engine/Source/Programs/MowoBuildTool/src/MowoBuildTool.Core/Assets/MdfCooker.cs" />. The loader parses through `MdfDocument::ParseFromString`, which detects the binary encoding by its magic, so a cooked class loads the same as its text source. `mbt cook --mdf-text` keeps the text instead.
