You never register a node. The node catalogue walks every reflected class and flattens its `MFUNCTION`s, so anything a module reflects is placeable <Source symbol="VisualScriptNodeCatalog" />. This page lists what ships: the `Statics` libraries, the functions every actor exposes on itself, the async actions and the standard macros. For each function's parameters, open the class in the API reference.

## How libraries appear

A reflected class whose name ends in `Statics` gets its own palette category: the leading `M` and the trailing `Statics` are dropped and `Library` is added, so `MGameplayStatics` is **Gameplay Library**. A placed node stores the qualified name, such as `MGameplayStatics::SpawnActorByClass`, and the VM calls it on the class's default object, so no target pin is needed. A `const` function is a pure node.

A library from a feature module or a plugin appears once that module is loaded and the plugin is enabled. Your game module's own `Statics` classes appear the same way.

## Functions on self

Without a library prefix, a call resolves on the running instance's own class chain. `AActor` exposes `GetActorLocation`, `SetActorLocation`, `GetActorName`, `SetActorHiddenInGame`, `GetComponentByClass`, `GetComponentByName` and `GetComponentCount` <Source symbol="AActor" />. A component returned by a getter is an object pin: call its functions with **Call On Target**. Pawn, Character, controller, game mode and game state classes reach their native base's reflected functions the same way. See [Calling C++](/docs/visual-scripting/calling-cpp/).

## Async actions

An **Async Action** node starts an action and resumes the graph on the pin the action fires. These ship with the engine:

| Action | Inputs | Fires |
| --- | --- | --- |
| Timed Wait | Duration | On Completed, with the elapsed time |
| Delay Until Next Tick | | On Next Tick |
| Wait For Gameplay Event | Event Name | On Event, with the payload |
| Async Load Asset | Asset Path | On Loaded with the asset, or On Failed |
| AI Move To | Pawn, Destination, Acceptance Radius | On Arrived, or On Failed |
| Wait Input Action | Action, Test Already Pressed | On Pressed with the seconds waited, then On Released with the seconds held; On Failed |
| Wait Overlap | Trigger, Tag Filter, Timeout | On Overlap with the entering actor, On Timeout, or On Failed |
| Wait Attribute Change | Target, Attribute, Trigger Once | On Changed with the new value, or On Failed |

Wait Input Action ignores a press already held when it starts unless **Test Already Pressed** is set. Wait Overlap counts only actors that enter after it starts; an empty Trigger means the graph's own actor. Wait Attribute Change keeps listening for the life of the graph unless **Trigger Once** is set.

<Callout type="warning">

Async Load Asset, AI Move To and the three Wait actions rely on a provider installed by a higher module: the asset system, the AI navigation module and the gameplay layer. In a host without one, the node takes On Failed on its first tick and logs what is missing.

</Callout>

A game module can add its own action, or replace a shipped one by registering under the same name, with `VisualScriptAsyncRegistry::Register` <Source symbol="VisualScriptAsyncRegistry" />.

## Standard macros

Two macros ship with the engine and appear under **Macros (Standard)** in every class:

| Macro | Inputs | Outputs | Does |
| --- | --- | --- | --- |
| `IsValidBranch` | `In` (exec), `Object` | `IsValid`, `NotValid` (exec) | Checks an object and branches in one node. |
| `ForEachWithBreak` | `In` (exec), `Array`, `Break` (exec) | `LoopBody` (exec), `Element`, `Index`, `Completed` (exec) | A For Each whose body can fire `Break` to stop early. |
