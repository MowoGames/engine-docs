Engine tests are [doctest](https://github.com/doctest/doctest) cases in six test executables, one per area of the engine. `mbt test` builds them, asks each one for its cases, runs every case in a process of its own, runs the build tool's C# unit tests, and judges the release build from outside. The result is one JUnit report.

This section covers the model, [running the suite](/docs/testing/running-tests/), [writing a test](/docs/testing/writing-tests/) and [what CI does and does not cover](/docs/testing/ci/).

## The test executables

Each area has a `Test` target under `Engine/Source/Developer/<Area>Tests` <Source path="Engine/Source/Programs/MowoBuildTool/src/MowoBuildTool.Core/Targets/TargetRegistry.cs" />:

| Executable | Covers |
|---|---|
| `CoreTests` | Core, Platform, memory, threading, ECS, reflection, the object model and GC, MDF, config, crash handling, localization, archives |
| `RuntimeTests` | Actors and worlds, AI, animation, audio, physics, assets and cooking, Visual Scripting, Arc and ArcUI, plugins, and the player against a staged package |
| `NetTests` | Replication, sessions, voice, online services, rollback, the dedicated server |
| `ProgramsTests` | The Project Launcher, the games launcher client and the crash reporter, compiled from their own sources |
| `RendererTests` | Render graph, materials, RHI, and every windowed GPU case |
| `MowoEditorTests` | The editor: headless panel and model tests, and in-process smokes and benches |

All six link `MowoTestKit`, a static library with the doctest runner and its `main`, the verdict sink `FTestReport` <Source symbol="FTestReport" />, the per-case options `FTestCaseOptions` <Source symbol="FTestCaseOptions" />, process helpers and the shared fixtures <Source path="Engine/Source/Developer/MowoTestKit/MowoTestKit.Build.cs" />. Test targets live in the `Developer` group, so they never reach a release or profile build.

<Callout type="engine">
No product carries test code. The editor, the player, the server and the launchers have no test switches. `MowoEditorTests` compiles the editor's sources into itself and drives them through a subclass of the editor engine, `NetTests` does the same for the server, and `RuntimeTests` hosts the player engine. A product that must be judged as shipped, such as the release player, is launched from outside and judged by its log, liveness and exit code.
</Callout>

## Kinds of case

- **Headless cases** run without a window or GPU. Most of `CoreTests`, `NetTests` and `ProgramsTests` are headless.
- **`[gpu]` cases** need a device. In `RendererTests` they run through a shared fixture that starts a fresh test engine with its own window and device for each case, on the host's default backend: D3D12 on Windows, Metal on macOS, Vulkan on Linux <Source path="Engine/Source/Developer/RendererTests/Private/TestEngineFixture.h" />. A case can name more backends and then also runs once per backend the host links.
- **`[packaged]` cases** run with a staged package of the test project, or of a template, as the working directory.

Tags in the case's suite string, such as `[core]` or `[renderer][gpu]`, say which is which, and `mbt test --tag` filters on them.

## Pass, fail and skip

A case has three outcomes, not two. It reports through `FTestReport` <Source path="Engine/Source/Developer/MowoTestKit/Public/TestKit/MowoTest.h" />:

| Call | Meaning | Process exit code |
|---|---|---|
| `FTestReport::ReportResult(true)` | Every check passed | 0 |
| `FTestReport::ReportResult(false)` | A check failed | 1 |
| `FTestReport::ReportSkipped("why")` | The case could not run. The reason goes to stderr as `TEST SKIPPED: why` | 77 |
| nothing reported | A hollow pass: the case fails | 1 |
| no case matched the filter | | 2 |

A failure outranks a skip, and a skip outranks a pass. A skip is for a precondition the case does not own: a missing fixture, a device feature the machine lacks, a backend the host cannot link. Write the reason as what is therefore **not covered**. `mbt test` exits 2 when anything skipped, unless you pass `--allow-skips`, so a run that left part of the suite out never reads as a full pass.

The runner adds two verdicts of its own:

- **CRASH.** A process that dies instead of reporting, by an access violation or a POSIX signal, is reported as `CRASH`, not `FAIL`.
- **Sanitizer report.** Under `--asan`, `--ubsan` or `--tsan`, a sanitizer report exits 86, 87 or 88 and the runner names it, so it never reads as an ordinary check failure <Source path="Engine/Source/Programs/MowoBuildTool/src/MowoBuildTool/Commands/TestCommand.cs" />.

## Hermetic by default

Every case runs **without the per-user config**: the kit adds `--no-user-config` before the case body runs, so a setting you saved in the editor cannot change what a test measures <Source path="Engine/Source/Developer/MowoTestKit/Private/TestCase.cpp" />. Cases that need a project open the test fixture project, `Engine/Source/Developer/MowoTestKit/Fixtures/TestProject/TestProject.mproject`, which holds the test scenes and fixtures. Running the suite rewrites that manifest; do not commit the churn.

## Release is judged from outside

A release binary carries no test code, so it cannot report on itself. On a full, unfiltered run, `mbt test` therefore also:

- compiles `-c release -t MowoGame` (`release-build`), the only build that exercises link-time optimization;
- relinks and recompiles part of it and requires byte-identical output (`deterministic-relink`, `deterministic-compile`);
- packages the test project in release, monolithic and modular, launches the packaged player and checks it starts, stays alive and exits cleanly on a window close (`release-launch-monolithic`, `release-launch-modular`);
- builds and boots the dedicated server's own tree (`server-target-cut`).

These rows go into the `judged-from-outside` suite of the report.

## The Automation panel

The editor can run cases without a terminal. The **Automation** panel (**Window › Debug › Automation**) asks the test executables for their cases with `--mowo-list-cases` and runs the ones you pick the way `mbt test` does, from outside the editor <Source path="Engine/Source/Editor/MowoEditor/Private/Panels/AutomationRunnerPanel.cpp" />. It shows pass, fail, skip and crash with the reason, and archives each case's log to `%TEMP%/mbt-test-<case>-*.log`. It never builds, so it tests whatever binaries are in `Engine/Binaries/<platform>/<config>/`, and it cannot run packaged cases, which need `mbt package` first.
