A quality tier is one setting that decides which rendering features run and how much each one may spend. Mowo has five tiers: **Low, Medium, High, Epic and Cinematic** (). High is the code default.

A tier only **scales what the project enabled**. Global Illumination, ray tracing, MegaLights, the volumetric cloud volume, volumetric fog and frame generation are project switches in **Project Settings > Rendering > Features**, all off for a new project ([Project Settings](/docs/editor/project-settings/#rendering)). A tier, a device profile, an `sg.*` group or an `r.*` cvar never turns one of them on while its switch is off, and the renderer does not build its targets or pipelines.

The rule is **the tier sets, the cvar refines**. A tier writes a whole row of values into `SceneRenderer::Options`; any `r.*` cvar that is not `-1` then overrides its one value. A tier change applies at the next `BeginScene`, and resources that change size, such as the shadow atlas or the probe grid, are recreated then. No restart is needed.

## Pick a tier

<Steps>
<Step title="In the editor">
Open **Edit > Engine Quality** and choose Low, Medium, High, Epic or Cinematic. **Auto (GPU-detected)** removes your choice and runs the detection again. The choice is saved to your user config and reapplied at every launch.
</Step>
<Step title="From the viewport">
Click **Quality** on the viewport toolbar. The card shows the active preset, a Low to Cinematic selector, one override row per category (View distance, Shadows, Global illum., Reflections, Textures, Effects, Foliage, Post process), the upscaler, and **Auto**, **Benchmark** and **Reset** buttons.
</Step>
<Step title="In Project Settings">
Open **Project Settings > Engine > Scalability**. It lists the preset and each category with its tier value and lets you pin individual ones.
</Step>
<Step title="In a shipped game">
The player settings screen has a **Quality Preset** row in the **Graphics** category that writes `r.Quality`, and rows for the most important single knobs (). A row the player sets stays where they put it when the preset changes.
</Step>
<Step title="From code or the console">
Set `r.Quality`: `0` is Low, `4` is Cinematic, `-1` means not set.
</Step>
</Steps>

## Where the tier comes from

The active tier is resolved in this order, highest first:

1. An explicit `r.Quality`: the user config, `Scalability.ini`, the editor menu, the in-game settings or `--cvar=r.Quality=N` in a development build.
2. A tier the platform recommends for the device. On Steam this is the recommended profile the developer set for that hardware.
3. The auto-tier, which fills only an unset slot.
4. The code default, High.

The editor and the game run the same auto-tier, so the editor viewport, Play In Editor and the shipped game pick the same tier on the same machine. Each logs a `[Quality]` line with the tier and why it was chosen.

## The auto-tier

 decides from a measurement when it has one and from the GPU's name and memory when it does not.

### Measured

On the first launch on a machine the engine runs a short synthetic GPU and CPU benchmark once and stores the result; later launches read it. The **Benchmark** button in the viewport Quality card runs it again. The GPU index maps to a tier, with 100 as a reference mid-range card:

| GPU index | Tier |
|---|---|
| Under 25 | Low |
| 25 to 55 | Medium |
| 55 to 150 | High |
| 150 to 240 | Epic |
| 240 and up | Cinematic |

VRAM still caps a measured tier: under 4 GB caps it at Medium, under 6 GB at High. `r.AutoQuality.Benchmark 0` ignores the measurement.

### From the device

Without a measurement:

| Device | Tier |
|---|---|
| Apple silicon Max or Ultra | Epic |
| Other Apple silicon | High |
| Integrated GPU | Low |
| Under 4 GB VRAM | Low |
| Under 6 GB VRAM | Medium |
| Older discrete GPUs matched by name | Medium |
| 20 GB or more, and a known high-end GPU or mesh shaders plus ray query | Cinematic |
| 12 GB or more, and a known high-end GPU or mesh shaders plus ray query | Epic |
| Anything else | High |

### Caps

- A device without mesh shaders is capped at High; one without ray query is capped at Epic.
- A slow CPU caps the tier: by its measured index when there is one, otherwise 4 or fewer logical cores cap at Medium and 8 or fewer at High.
- Under 8 GB of system RAM drops to Low; under 16 GB caps at High.

An unknown core count or RAM size never lowers the tier.

<Callout type="tip">
Simulate another machine with `r.AutoQuality.ForceVRAMMB`, `r.AutoQuality.ForceIntegrated`, `r.AutoQuality.ForceName`, `r.AutoQuality.ForceCores` and `r.AutoQuality.ForceRamMB`. Forcing a device skips the stored measurement.
</Callout>

### Device profiles

After the tier is known, a device profile can adjust a few values that nothing else has claimed. The Steam Deck profile applies at Low: it moves `sg.GlobalIlluminationQuality` to Medium so the Deck keeps Global Illumination, caps the frame rate at 40 with `t.MaxFPS`, and sets the dynamic-resolution target to 22 ms (). A value you set explicitly always wins over a profile.

### Upscaler choice

The auto-tier also picks the anti-aliasing method. It chooses the engine's TSR, or TAA when the tier renders at native resolution (Cinematic). Vendor upscalers (DLSS, FSR, XeSS, MetalFX) are picked automatically only when `r.AutoQuality.VendorUpscalers` is 1. See [Upscaling and anti-aliasing](/docs/rendering/upscaling-and-anti-aliasing/).

## What each tier turns on

Values come from the tier rows in. The **Project switch** column names the switch a row also needs; with it off the row is off at every tier (`FScalabilityTiers::GetComposed` clears it, and `FScalabilityTiers::Get` keeps the raw table).

| Feature | cvar | Project switch | Low | Medium | High | Epic | Cinematic |
|---|---|---|---|---|---|---|---|
| Clustered lighting | — | — | on | on | on | on | on |
| Auto-exposure | — | — | on | on | on | on | on |
| Bloom, motion blur, contact shadows | — | — | off | on | on | on | on |
| Global Illumination | `r.DDGI` | Global Illumination | off | on | on | on | on |
| Screen-space reflections | `r.SSR` | — | off | on | on | on | on |
| GTAO | `r.GTAO` | — | off | on | on | on | on |
| Screen-space subsurface scattering | — | — | off | on | on | on | on |
| SDF far sun shadows | `r.Shadow.SdfFar` | Global Illumination | off | on | on | on | on |
| Screen-probe final gather | — | Global Illumination | off | off | on | on | on |
| Depth prepass | `r.DepthPrepass` | — | off | off | on | on | on |
| PCSS soft shadows | `r.Shadow.Soft` | — | off | off | on | on | on |
| Translucent reflections | `r.Reflections.Translucent` | Global Illumination | off | off | on | on | on |
| Terrain runtime virtual texture | `r.Terrain.RVT` | — | off | off | on | on | on |
| Cloud shadows | `r.Clouds.Shadows` | Volumetric Clouds | off | off | on | on | on |
| Virtual shadow maps | `r.VSM` | — | off | off | off | on | on |
| MegaLights | `r.MegaLights` | MegaLights | off | off | off | on | on |
| Ray-traced reflections | `r.RTReflections` | Ray Tracing | off | off | off | on | on |
| Ray-traced AO | `r.RTAO` | Ray Tracing | off | off | off | on | on |
| Hardware ray-traced GI gather | `r.GI.HWRTGather` | Global Illumination + Ray Tracing | off | off | off | on | on |
| SDF reflections and the near radiance cascade | `r.GI.NearCascade` | Global Illumination | off | off | off | on | on |
| Volumetric fog | `r.VolumetricFog` | Volumetric Fog | off | off | off | on | on |
| Meshlet G-Buffer | `r.MeshletGBuffer` | — | off | off | off | on | on |
| Ray-traced sun shadows | `r.RTShadows` | Ray Tracing | off | off | off | off | on |

Most of these cvars take `-1` for the tier value and `0` or `1` to force the feature. `r.GI.NearCascade` and `r.Reflections.Translucent` are gates instead: they default to `1` and let the tier's choice through; set `0` to turn the feature off.

Ray-traced rows need ray query on the device, and the meshlet path needs mesh shaders. Without them the feature falls back each frame, see [Ray tracing](/docs/rendering/ray-tracing/). SSGI is off at every tier; `r.SSGI 1` forces it when Global Illumination is on. The raymarched cloud volume (Epic and Cinematic pick it once clouds are on) also needs **Volumetric Clouds**; without it a cloud actor draws the flat cloud layer at every tier.

## Scalability groups

One dial is sometimes too blunt: a machine can be short of fill rate and long on memory. The `sg.*` cvars pick which tier row a group of settings comes from, while everything else follows `r.Quality` ().

| cvar | Controls |
|---|---|
| `sg.ViewDistanceQuality` | LOD thresholds and bias, small-object and occlusion culling, view distance, meshlet G-Buffer, depth prepass |
| `sg.ShadowQuality` | Clustered lighting, sun and local shadows, contact shadows, PCSS, VSM, MegaLights, SDF far and ray-traced sun shadows |
| `sg.GlobalIlluminationQuality` | Global Illumination on or off and its budgets, GTAO and ray-traced AO |
| `sg.ReflectionQuality` | SSR, SDF, ray-traced and translucent reflections |
| `sg.PostProcessQuality` | Bloom, motion blur, depth of field kernel, auto-exposure, subsurface scattering |
| `sg.AntiAliasingQuality` | Render scale and upscaler quality |
| `sg.TextureQuality` | Anisotropy, terrain virtual texture |
| `sg.EffectsQuality` | Particle budgets, volumetric fog, clouds |
| `sg.FoliageQuality` | Foliage density |

Each group defaults to `-1` (follow `r.Quality`). Set one to `0` through `4` to pin it. For example, `sg.GlobalIlluminationQuality=0` keeps everything else at the base tier and turns Global Illumination off, because its on/off switch is part of the row.

## Scalability.ini

A project can tune tiers and groups in config. The engine reads `Scalability.ini` through the usual layers: `Engine/Config/BaseScalability.ini`, the project's `Config/DefaultScalability.ini`, a platform folder, then `Saved/Config/Scalability.ini` ().

```ini title="Config/DefaultScalability.ini"
[ConsoleVariables]
r.Quality=2

[ScalabilityGroups]
sg.ShadowQuality=3

[ShadowQuality@3]
r.Shadow.MaxDistance=250
```

- `[ConsoleVariables]` sets cvars.
- `[ScalabilityGroups]` pins `sg.*` groups.
- A `[<Group>@<Level>]` section sets extra cvars while that group is pinned to that level. The group name drops the `sg.` prefix.

Values from this file sit below every other INI and below the player's own settings.

## Dynamic resolution

`r.DynamicRes 1` steers the render scale toward a GPU frame-time target between `r.DynamicRes.MinScale` and `r.DynamicRes.MaxScale`. The default, `-1`, turns it on in the shipped game and off in the editor viewport.

| cvar | Default | Meaning |
|---|---|---|
| `r.DynamicRes` | -1 | -1 auto, 0 off, 1 on |
| `r.DynamicRes.TargetMs` | 16.6 | GPU frame-time target in milliseconds |
| `r.DynamicRes.MinScale` | 0.6 | Lowest render scale |
| `r.DynamicRes.MaxScale` | 1.0 | Highest render scale |

A scale step reallocates nothing: passes render into a sub-rectangle of full-size targets, so temporal histories survive it.

## Troubleshooting

- **A tier change does not show.** Setting `r.Quality` back to `-1` at runtime leaves the current options in place. Set `0` to `4`, or pick **Auto** in the editor menu to run detection again.
- **An RT feature is on but nothing changes.** The device or backend has no ray query, so the raster fallback runs. D3D11 never has it.
- **Every knob jumps when you pick a preset in the game's settings.** Only rows still at their tier value follow the preset; a row the player changed keeps its value.
