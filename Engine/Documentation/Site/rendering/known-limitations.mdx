Mowo is pre-1.0 (version <Fact id="engine.version" />). The renderer covers a lot of ground, but some features are written without having been verified on the hardware they target, and some have known gaps. Read this page before you plan a project around a feature.

## Written but not verified on hardware

<Callout type="warning">
Each backend is compiled on every build, but GPU tests run only on the backends and GPUs of the machine that runs them. No single machine checks all four backends.
</Callout>

- **Frame generation** (FSR3, DLSS-G, XeSS-FG, MetalFX) is written but not verified on the GPUs it targets, and not validated with HDR swapchains. See [Upscaling and anti-aliasing](/docs/rendering/upscaling-and-anti-aliasing/#frame-generation).
- **DLSS Ray Reconstruction** (`r.DLSS.RayReconstruction`) is off by default.
- **Vendor upscalers** are not picked automatically; the auto-tier uses TSR unless `r.AutoQuality.VendorUpscalers` is 1.
- **The neural irradiance cache** (`r.GI.NeuralCache`) is console-only and off by default. It costs more than the regular gather and its color does not match yet.

## Platforms

- **Linux does not build end to end.** Most third-party libraries the engine builds from source have no Linux binaries in the tree yet.
- **macOS builds are not notarized**, so a shipped Mac build needs extra steps to launch on another machine.

## Backends

| Backend | Limits |
|---|---|
| Direct3D 11 | No meshlets, ray tracing, bindless resources, async compute, indirect-count draws or frame generation. FSR is unavailable. Players reach D3D11 automatically when D3D12 fails, so test on it. |
| Metal | Bindless resources and 64-bit shader integers are reported off, so the path tracer does not run. No ray-tracing pipelines, so features that need per-material hit shaders use inline ray query. Mesh shaders are experimental and off by default. No Reflex, Anti-Lag 2 or XeLL. HDR mastering metadata is not sent. |
| Vulkan | No XeSS frame generation. No AMD Anti-Lag 2 or Intel XeLL. |

See [Backends](/docs/rendering/backends/#what-each-api-can-do) for the full table.

## Lighting and shadows

- **Low has only baked indirect light.** The live Global Illumination is off at Low; it samples a baked field when the scene has one. See [Global Illumination](/docs/rendering/global-illumination/#bake-a-fallback-for-low).
- **The distance field is finite and camera-centred.** Distance-field Global Illumination, reflections and far shadows only see geometry inside its window.
- **The sun's virtual shadow map skips GPU foliage, terrain and world-position-offset materials.** Those shadows come from the cascades.
- **Area-light shadows** are a projection from the light's centre, not a true area solve.
- **MegaLights** is sampling with a temporal and spatial denoise, not a full ReSTIR stack, and its lights ignore light functions.

## Feature scope

- **Substrate** is two slabs, off by default, with no per-slab normal and four albedo modes. See [Materials](/docs/rendering/materials/#substrate).
- **The path tracer** is a reference: diffuse and GGX only, no glass or water, and the environment is the sky cubemap. It needs ray query and 64-bit shader integers.
- **Gaussian splats** do not cast or receive shadows, are invisible to ray tracing and Global Illumination, and do not import view-dependent color.
- **Virtual texturing** drives the terrain and one test surface; general materials cannot mark a texture as virtual.
- **The render graph** orders passes and emits barriers, but the scene renderer does not use its dead-pass culling.
