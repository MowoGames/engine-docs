Every engine shader is written once in HLSL under `Engine/Shaders/` and compiled for all four backends. `mbt shaders` produces a blob per target for every shader variant and stage and packs them into `Shaders.meaf`, which each backend reads at runtime.

## One source, four targets

<Flow steps={["HLSL in Engine/Shaders", "DXC to SPIR-V (Vulkan)", "DXC to DXIL (D3D12)", "FXC to DXBC (D3D11)", "spirv-cross to MSL (Metal)", "Shaders.meaf"]} caption="mbt shaders compiles every variant and stage per target and packs the blobs into one archive." />

| Target | Backend | Compiler |
|---|---|---|
| SPIR-V | Vulkan | DXC |
| DXIL | Direct3D 12 | DXC |
| DXBC (Shader Model 5.0) | Direct3D 11 | FXC |
| MSL | Metal | spirv-cross; `--metallib` on a Mac also builds `.metallib` |

Without `--targets`, `mbt shaders` builds the set for the platform: Windows gets SPIR-V, DXIL and DXBC; Linux gets SPIR-V; macOS gets SPIR-V and MSL. The compilers are vendored, so no separate SDK is needed.

Some shaders cannot run on every backend, such as mesh shaders and ray-query variants on D3D11. Those are excluded from that target, and the backend gates the feature off through its capabilities before it asks for them. `mbt shaders --report-matrix --check` fails when a variant that should compile stops compiling.

## Build shaders

```powershell
./mbt.cmd shaders
./mbt.cmd shaders --targets spirv,dxil,dxbc,msl
./mbt.cmd shaders --project MyGame/MyGame.mproject
./mbt.cmd shaders --workers auto
./mbt.cmd shaders --report-matrix --check
```

`--project` also compiles your project's material permutations. `--workers` spreads compilation over several worker processes, and `--ddc` reuses blobs from a shared cache. See the [mbt reference](/docs/reference/mbt-cli/) for every option.

At runtime, shaders load from the `Shaders` mount. A loose `Shaders/` folder next to the binary sits above `Shaders.meaf`, so its files override the archive.

## Folders and virtual paths

| Folder | Contents |
|---|---|
| `Engine/Shaders/Public/` | Headers any shader may include: `MowoBindings.hlsli`, `LitVertex.hlsli`, `Skinning.hlsli`, the ray-tracing record helpers |
| `Engine/Shaders/Private/<Pass>/` | The compiled shaders, one folder per area: `GBuffer`, `Lighting`, `GI`, `Shadow`, `RayTracing`, `PostProcess`, `Forward`, `Sky`, `Volumetrics`, `Water`, `Particles` and others |
| `Engine/Shaders/Shared/` | Structs both C++ and HLSL read, scalars only (`MowoSharedTypes.hlsli`) |

Include across folders by **virtual path**, never by a relative walk such as `../Common/…`:

```hlsl
#include "/Engine/Public/MowoBindings.hlsli"
#include "/Engine/Private/PostProcess/HdrEncode.hlsli"
#include "GiClipmap.hlsli"
```

A file in the same folder is included by name. Other roots are `/Plugin/<Name>/…`, `/Project/…` and `/Test/…`. A module declares the roots it owns in its `Build.cs` with `AddShaderSourceDirectoryMapping`, so a plugin can ship its own shaders.

The archive keys shaders by **blob key**. `Shader::Create` takes either form (<Source symbol="FShaderPath" />):

| Virtual source | Blob key |
|---|---|
| `/Engine/Private/GBuffer/GBufferFill.hlsl` | `GBuffer/GBufferFill` |
| `/Plugin/Foo/Private/Bar.comp.hlsl` | `Plugin/Foo/Bar` |
| `/Project/Private/Water.hlsl` | `Project/Water` |

Engine keys stay bare; other roots are prefixed, so a plugin's `Lighting/X` cannot shadow the engine's.

## Binding macros

Shaders never write `[[vk::...]]` attributes directly. Every source includes `MowoBindings.hlsli` and uses its macros, so the same text compiles for SPIR-V and for the D3D and Metal formats:

| Macro | Under SPIR-V | On other targets |
|---|---|---|
| `MOWO_BINDING(binding, set)` | `[[vk::binding(binding, set)]]` | Removed; the `register()` annotation carries the D3D binding |
| `MOWO_PUSH_CONSTANTS(Type, name)` | `[[vk::push_constant]] Type name` | A `cbuffer` at `register(b13)` |
| `MOWO_LOCATION(n)` | `[[vk::location(n)]]` | Removed |
| `MOWO_IMAGE_FORMAT("rgba16f")` | `[[vk::image_format(...)]]` | Removed |

Register `b13` is reserved engine-wide for push constants.

### Example: a fullscreen pass

This follows the structure of the engine's `PostProcess/FXAA.hlsl`: a fullscreen triangle with no vertex buffer, one texture, one sampler and a push-constant block.

```hlsl title="Private/Desaturate.hlsl"
#include "/Engine/Public/MowoBindings.hlsli"

MOWO_BINDING(0, 0) Texture2D InputTexture : register(t0);
MOWO_BINDING(1, 0) SamplerState InputSampler : register(s0);

struct PushConstants {
    float Amount;
    float UVScaleX;
    float UVScaleY;
    float Pad;
};
MOWO_PUSH_CONSTANTS(PushConstants, pc);

struct VSOutput {
    float4 Position : SV_POSITION;
    float2 TexCoord : TEXCOORD0;
};

VSOutput VSMain(uint vertexID : SV_VertexID) {
    VSOutput output;
    output.TexCoord = float2((vertexID << 1) & 2, vertexID & 2);
    output.Position = float4(output.TexCoord * 2.0 - 1.0, 0.0, 1.0);
    output.Position.y = -output.Position.y;
    return output;
}

float4 PSMain(VSOutput input) : SV_TARGET {
    float2 uv = MowoRenderUV(input.TexCoord, float2(pc.UVScaleX, pc.UVScaleY));
    float3 color = InputTexture.SampleLevel(InputSampler, uv, 0).rgb;
    float luma = dot(color, float3(0.2126, 0.7152, 0.0722));

    return float4(lerp(color, luma.xxx, saturate(pc.Amount)), 1.0);
}
```

The UV scale is there because passes render into the top-left part of full-size targets when the render scale is below 1. Remap with `MowoRenderUV` or `MowoRenderUVClamped` from `MowoBindings.hlsli`.

## Entry points and stages

DXC emits one blob per stage. Entry points are fixed by stage:

| Entry point | Stage |
|---|---|
| `VSMain` | Vertex |
| `PSMain` | Pixel |
| `CSMain` | Compute (`.comp.hlsl` sources) |
| `MSMain` | Mesh (`.mesh.hlsl` sources, compiled with a pixel stage) |
| `ASMain` | Task / amplification (optional in a `.mesh.hlsl` source) |

Variants come from permutations: `Shader::Create(name, path, permutation)` loads one, and falls back to the base shader when that variant was not compiled (<Source symbol="ShaderPermutation" />).

## Hot reload

The editor reloads shaders while it runs:

1. Run `./mbt.cmd shaders --watch`. It recompiles a changed `.hlsl`, including every shader that includes a changed header, and copies the new SPIR-V into the loose `Shaders/` overlay beside the binary.
2. The editor watches that overlay and, once the folder settles, reloads at the start of the next frame: it waits for the GPU, reloads every live shader and rebuilds only the pipelines whose bytecode changed.
3. A compile that fails never reaches the overlay, so a broken edit keeps the previous shader.

The watcher writes SPIR-V, so this loop applies to the Vulkan backend: launch the editor with `-vulkan` while you iterate on hand-written shaders. Material graphs reload on every backend after their background compile, see [Materials](/docs/rendering/materials/).

## Rules every shader follows

- **Matrices are row-major.** Declare `row_major float4x4` in cbuffers and push constants. In structured buffers, DXIL ignores majority annotations, so store `MowoMat4Rows` and convert with `MowoMat4FromRows` and `MowoMat4ToRows`.
- **Do not put `float3` in a `StructuredBuffer`.** DXC gives it a 16-byte stride and packed 12-byte data reads sheared. Use a struct of three floats.
- **Give every added cbuffer an explicit `register(bN)`** when an include already declares one without a register. The D3D backends can recover only one register-less cbuffer per stage.
- **Stay within 16 samplers per stage for DXBC.** Shader Model 5.0 has `s0` to `s15`.
- **Rebuild normal-map Z.** Normal maps are BC5, which has two channels. Unpack with `MowoUnpackTangentNormal`.
- **Build the bitangent with `MowoBitangent(N, T)`** so mirrored UV shells light correctly, and transform normals with `MowoTransformNormal`.
- **Share structs through `Shaders/Shared/`.** A struct both C++ and HLSL read lives there once, with scalar fields only.
