`mbt package-editor` builds Mowo's counterpart to Unreal's Installed Build: an installable bundle with **Mowo Editor**, the **Mowo Project Launcher** and a game-module SDK <Source path="Engine/Source/Programs/MowoBuildTool/src/MowoBuildTool/Commands/PackageEditorCommand.cs" />. Developers on your team install it, create projects from templates, and compile their game's C++ modules against the prebuilt engine, without cloning or building the engine repository.

This is for distributing the tools to a team. To ship a game to players, use [`mbt package`](/docs/shipping/package-a-game/).

## Build the installed editor

Run it from a full engine checkout on Windows:

```powershell
./mbt.cmd package-editor
./mbt.cmd package-editor -o D:/Builds/MowoEditor --zip
./mbt.cmd package-editor --sign D:/Secrets/MyStudio.pfx
./mbt.cmd package-editor --skip-build --skip-shaders
```

| Option | Default | Meaning |
|---|---|---|
| `-c, --config` | Release | Configuration the installed engine ships as |
| `-o, --out` | `build/Package/MowoEditor` | Output folder |
| `--zip` | off | Also write `MowoEditor-<version>-<config>.zip` |
| `--installer` | on | Write an installer (see below) |
| `--sign` | none | Code-sign the executables and engine DLLs; falls back to `MOWO_SIGN_CERT` |
| `--skip-build`, `--skip-shaders` | off | Reuse the binaries in `Engine/Binaries/<Platform>` and the build tree's shader archive |

The command builds the engine, stages the binaries, compiles the editor's shader set, stages the SDK, the templates and the build toolchain, then builds the distributables. It refuses to run on a non-Windows host, and from inside an installed build.

## What is inside

The bundle is laid out like the checkout it came from, so the editor and `mbt` find everything where they find it in a source tree <Source path="Engine/Source/Programs/MowoBuildTool/src/MowoBuildTool.Core/Packaging/EditorPackageLayout.cs" />:

```text
MowoEditor/
├── InstalledBuild.txt               marker: version, configuration, platform
├── Manifest.txt                     sha256 + size of every shipped file
├── mbt.cmd, mbt.sh                  forwarders to the shipped mbt
├── Engine/
│   ├── EngineManifest.json          engine-root marker and version source
│   ├── Binaries/Win64/              MowoEditor, MowoProjectLauncher, MowoGame, MowoServer,
│   │                                MowoCrashReporter, MdfTool, MeafBuilder, engine and vendor DLLs,
│   │                                the VC++ runtime, Shaders.meaf, EngineContent.meaf
│   ├── Source/<Group>/**            every .Build.cs and .Target.cs, and the Public/ header trees
│   ├── Source/ThirdParty/**         the include folders and libraries game modules need
│   ├── Source/Programs/MowoBuildTool/publish/   self-contained mbt
│   ├── Lib/Win64/                   engine import libraries
│   ├── Config/                      the engine's Base*.ini layer
│   └── Legal/ThirdPartyNotices.txt  license texts of the shipped libraries
├── Templates/TP_*/**                Project Launcher templates
└── Samples/StarterContent/**        the optional starter pack a new project can add
```

The binaries keep the names of the configuration they were built in, picked out of the shared `Engine/Binaries/<Platform>` by their suffix <Source path="Engine/Source/Programs/MowoBuildTool/src/MowoBuildTool.Core/Modules/BinaryLayout.cs" />. No PDBs ship.

The third-party slice is not hand-picked. The packager resolves the canonical game module (`MowoSandbox`, the same shape every template uses) and stages exactly the include folders and libraries its closure references <Source path="Engine/Source/Programs/MowoBuildTool/src/MowoBuildTool.Core/Packaging/EditorPackager.cs" />. Programs ship their rules only.

## How the installed `mbt` behaves

`InstalledBuild.txt` at the root switches `mbt` into installed mode <Source path="Engine/Source/Programs/MowoBuildTool/src/MowoBuildTool.Core/Config/InstalledEngine.cs" />:

<Flow steps={["mbt build -t MyGame", "Engine modules: prebuilt DLL + import lib", "Compile only project modules", "Link against Engine/Lib"]} caption="In installed mode only project modules compile." />

- **Engine modules are prebuilt.** They resolve to the shipped DLLs in `Engine/Binaries/<Platform>` and the import libraries in `Engine/Lib/<Platform>`, and are never recompiled.
- **A bare `mbt build` is refused.** Name a project module: `mbt build -t <GameModule> --extra-source <Project>/Source` <Source path="Engine/Source/Programs/MowoBuildTool/src/MowoBuildTool.Core/Build/BuildOrchestrator.cs" />.
- **The configuration is pinned.** A game module always builds in the configuration the engine shipped as, because mixing C runtime flavors across the DLL boundary does not work. A different `-c` is corrected, with a log line.
- **Reflection code generation still runs**, through the header tool built into the shipped `mbt`.

### Build a game from an installed build

```powershell
./mbt.cmd init MyGame -o D:/Projects/MyGame
./mbt.cmd build -t MyGame --extra-source D:/Projects/MyGame/Source
```

Or create the project from a template in the Project Launcher, and compile it from the editor. The [programming section](/docs/programming/) covers game modules.

<Screenshot id="shipping-project-launcher-installed" alt="Mowo Project Launcher started from the Start Menu shortcut of an installed editor build, showing the template wizard with the template list and the project name and location fields." />

Machines that compile game modules need the toolchain `Engine/Config/Toolchains.ini` pins: LLVM (clang-cl and lld-link), plus the Visual C++ toolset and Windows SDK that clang-cl builds against <Source path="Engine/Config/Toolchains.ini" />. They do not need the .NET SDK, because the shipped `mbt` is self-contained. Run `mbt doctor` to check a machine.

## The installer

With WiX `candle` and `light` on `PATH`, the installer is a per-user MSI. It installs under `%LOCALAPPDATA%\Programs` without an admin prompt and adds Start Menu shortcuts for **Mowo Project Launcher** and **Mowo Editor**. Its UpgradeCode is a fixed constant, so every later version upgrades in place <Source path="Engine/Source/Programs/MowoBuildTool/src/MowoBuildTool.Core/Packaging/InstallerGenerator.cs" />.

Without WiX, you get the self-extracting PowerShell installer plus the zip it unpacks; the zip is produced automatically in that case.

## Limitations

- **Windows only.** The layout is parameterized by platform, but the command refuses other hosts.
- **Keep the per-user install.** Project builds write under the install root, which a read-only Program Files install could not.
- **No dedicated server rebuild.** `MowoServer` ships from the shared build. The Server target's own module set would have to recompile engine modules, which installed mode refuses, so build server packages from a source checkout.
