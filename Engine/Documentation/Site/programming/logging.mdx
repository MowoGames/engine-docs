The Logging module writes every message to a set of sinks: the console, a log file, and in the editor the Output Log. Messages carry a level and a category, and each category has its own threshold you can change at run time. <Source symbol="Logger" />

## Logging a message

```cpp wrap
#include "Logging/Logger.h"

const int32_t count = 12;
const char* path = "Content/Textures/Rock.tex";

MOWO_LOG_INFO("Loaded %d meshes", count);
MOWO_LOG_DISPLAY("Wave %d started", count);
MOWO_LOG_WARN("Texture %s missing", path);
MOWO_LOG_ERROR("Device lost");
MOWO_LOG_DEBUG("Streaming pass done");
```

The macros take a `printf`-style format. The levels, quietest first, are Unreal's verbosities under the engine's names:

| Level | Unreal name | Macro | Where it goes by default |
| --- | --- | --- | --- |
| `Trace` | VeryVerbose | `MOWO_LOG_TRACE` | Nowhere until the category is lowered; compiled only in builds with debug logs |
| `Debug` | Verbose | `MOWO_LOG_DEBUG` | Nowhere until the category is lowered; compiled only in builds with debug logs |
| `Info` | Log | `MOWO_LOG_INFO` | Log file and console; the Output Log shows it for your own categories |
| `Display` | Display | `MOWO_LOG_DISPLAY` | Everywhere, the Output Log included |
| `Warning`, `Error` | Warning, Error | `MOWO_LOG_WARN`, `MOWO_LOG_ERROR` | Everywhere |
| `Fatal` | Fatal | `MOWO_LOG_FATAL` | Everywhere; never compiled out |

| Helper | What it does |
| --- | --- |
| `MOWO_LOG_INFO_ONCE`, `MOWO_LOG_WARN_ONCE`, `MOWO_LOG_ERROR_ONCE`, `MOWO_LOG_ONCE(Level, …)`, `MOWO_LOG_CAT_ONCE(Category, Level, …)` | Logged the first time the line runs |
| `MOWO_LOG_WARN_RATE_LIMITED(seconds, …)`, `MOWO_LOG_RATE_LIMITED(Level, seconds, …)`, `MOWO_LOG_CAT_RATE_LIMITED(Category, Level, seconds, …)` | The first line, then at most one per interval, followed by how many were held back |
| `MOWO_LOG_RENDER`, `MOWO_LOG_PHYSICS`, `MOWO_LOG_AUDIO`, `MOWO_LOG_INPUT`, `MOWO_LOG_SCRIPT`, `MOWO_LOG_NET` | Debug level in the matching built-in category |

Use `Display` for the few lines a developer using the editor should see: something they did finished, or the state they are working in changed. Detail that helps someone reading a bug report is `Info`. Per-item and per-frame detail is `Debug`.

Debug logs (`MOWO_DEBUG_LOGS`) are on in builds with assertions (`debug`, `dev` and `debuggame`) and off otherwise. A translation unit can force either by defining `MOWO_DEBUG_LOGS` itself. <Source path="Engine/Source/Runtime/Logging/Public/Logging/Logger.h" />

## Categories

A category is a named channel with its own threshold. Every message in a game module that names none goes to `LogGame`. Declare your own in a header with your module's export macro, define it in exactly one `.cpp` of that module, and log to it with `MOWO_LOG_CAT`:

```cpp nocompile
MOWO_DECLARE_LOG_CATEGORY(MYGAME_API, LogAI, Info);

MOWO_DEFINE_LOG_CATEGORY(LogAI, Info);

MOWO_LOG_CAT(LogAI, Warning, "lost the path: %s", name);
```

A category your game module or plugin defines is your own: the editor's Output Log shows its `Info` lines, where it hides the engine's below `Display` unless **Show engine logs** is on. Define the category once and export it: an inline definition would give every DLL its own copy, and changing the level would reach only one of them. A message below its category's threshold costs one atomic load and is dropped before its arguments are formatted.

## Changing a category's verbosity

```text
log                          list every category and its level
log LogRender                print one category's level
log LogRender Verbose        lower LogRender to Verbose
log LogRender warning        raise LogRender's threshold to Warning
log LogRender reset          restore the declared level
log global Warning           every category at once
```

Type it in the editor's Output Log or the game console. Levels are case-insensitive and take either spelling (`Verbose` or `debug`, `Log` or `info`); `All` is VeryVerbose and `Off` leaves only Fatal.

The same instructions come from two more places, applied at startup and again when a project opens. The command line wins over the INI:

```bash
MyGame.exe --logcmds="LogAI Verbose, LogRender Warning"
```

```ini title="Config/DefaultEngine.ini"
[Core.Log]
LogAI=Verbose
LogRender=Warning
```

A category that is not loaded yet, such as one in a game module or plugin, takes its level when its module loads.

## Keep the log readable

Every category starts at `Info` in every build, so a `Debug` line is quiet until someone asks for it. For anything that can fire more than once a second:

- make it `Debug`, or gate it behind a console variable that defaults to off,
- log on change or once (`MOWO_LOG_WARN_ONCE`) when the message reports a state,
- rate-limit it (`MOWO_LOG_WARN_RATE_LIMITED(5.0, …)`) when every occurrence matters but not every line,
- never log unconditionally from a per-frame path, including failure branches.

Outside `release` and `profile` builds a flood guard watches each category. When one writes more than 20 lines a second for three seconds in a row, it warns once, naming the call site that wrote the most. `FloodGuardLinesPerSecond=` under `[Core.Log]` changes the budget; `0` turns the guard off.

## Release builds

A `release` or `profile` build passes no source file names into the binary, and messages below a compile-time floor are removed entirely, format string included. The floor is Info by default; `mbt package --log-floor warning` raises it. See [Shipping](/docs/shipping/).

A `release` game keeps its console and file logs off unless it is started with `--log` or the project's engine config sets `logging.enabled=true`; a `profile` build keeps them on. With logging on, `--loglevel=info` lowers the threshold.

## Where files go

With a project open, logs go to `<Project>/Saved/Logs/`. Without one they go to the per-user folder, `%LOCALAPPDATA%\MowoEngine\Saved\Logs\` on Windows (a packaged game uses its own product name instead of `MowoEngine`). Files are named `Mowo_<date>_<time>_<pid>.log`, and the newest five per folder are kept. <Source path="Engine/Source/Runtime/Core/Public/Core/Constants.h" />

The file sink buffers lines and writes them on a background thread, so a slow disk never stalls the thread that logs. `Logger::Flush()` writes the buffer on demand, and the crash handler flushes it before it copies the log next to a crash dump.
