The **Http** module wraps a vendored, statically linked libcurl. Every HTTP request the engine makes goes through it, from crash uploads to the games launcher and GameNet's WebSockets. Add `"Http"` to your module's dependencies to use it. <Source symbol="HttpClient" />

TLS comes from the platform: Schannel on Windows, and the vendored mbedTLS on macOS and Linux. There is no OpenSSL dependency.

Every handle is built with the same transport rules: the peer certificate and host name are verified, TLS 1.2 is the minimum, only `http` and `https` (plus `ws` and `wss` for WebSockets) are accepted, a redirect may only land on `http` or `https`, and a redirect chain is cut after eight hops. A request to a `file://` or `ftp://` URL, or a redirect there, fails with an error instead of reading local files. A TLS handshake against a cleartext port fails; it never falls back to plain HTTP.

## Requests

`HttpClient` has only static functions. Each call uses its own curl handle, so calls from several threads at once are safe. Calls block, so run them on a job or a worker thread, never on the game thread.

```cpp wrap
#include "Http/HttpClient.h"

#include <string>
#include <vector>

const std::vector<std::string> headers = { "Content-Type: application/json" };

const Mowo::HttpResponse response = Mowo::HttpClient::Post("https://example.com/api/scores", "{\"score\":4200}", headers);
if (!response.Ok()) {
	const std::string reason = response.error.empty() ? response.body : response.error;
}

const Mowo::HttpResponse page = Mowo::HttpClient::Request("GET", "https://example.com/api/status");
```

| Function | Use |
| --- | --- |
| `Post(url, body, headers, timeoutSeconds)` | POST a string body |
| `Request(method, url, body, headers, timeoutSeconds)` | Any verb; a `GET` with a body is refused |
| `PostMultipart(url, fields, files, headers, timeoutSeconds)` | A `multipart/form-data` upload with form fields and files |
| `Fetch(url, options)` | A GET into memory that can be cancelled, throttled and observed |
| `Download(url, filePath, options, resume)` | Stream a body to a file, resuming a partial file |

`HttpResponse` carries the status code (0 for a transport failure), the body, a curl error message, and `nameNotResolved`, set when the host name did not resolve: usually a wrong URL rather than a network outage. `retryAfterMs` holds the server's `Retry-After` when it sent one as a number of seconds (0 otherwise; the HTTP-date form is ignored).

## Watching requests

Every request the engine makes through `HttpClient` is recorded in a bounded log (the last 512). Each record keeps the method, URL, status and error, bytes sent and received, the masked request headers (credentials are replaced with `<redacted>`), the first 4 KB of the response, and the time split into DNS, connect, TLS, wait for the first byte and transfer. <Source symbol="FHttpRequestLog" /> `FHttpRequestLog::ComputeStats` gives the count, error rate, average, median and 95th percentile latency, and `BandwidthSeries` gives bytes per second over time.

In the editor, **Window ▸ Debug ▸ Web Requests** shows the same data live: totals and latency figures, a 60 second bandwidth graph, a list of requests, and for the selected one its timing bar, headers and sizes. The log can be switched off with `FHttpRequestLog::Get().SetEnabled(false)`.

## Retrying transient failures

`HttpClient::Request` makes one attempt. `HttpRetry::Request(method, url, body, headers, timeoutSeconds, cancel)` takes the same arguments and retries a transient failure with exponential backoff before it gives up. <Source symbol="HttpRetry" /> It retries a transport error and the statuses 408, 425, 429, 500, 502, 503 and 504, and returns anything else (a 404, a 401, a 400) at once. The wait starts at `http.Retry.BaseDelayMs`, doubles each time up to `http.Retry.MaxDelayMs`, and is spread by `http.Retry.JitterPercent` so clients that failed together do not come back together. When the server sent `Retry-After`, the wait is at least that long, cut to `http.Retry.MaxRetryAfterMs`. A `cancel` flag you pass ends the wait early and returns the last answer.

Only requests that are safe to repeat are retried: `GET`, `HEAD`, `PUT`, `DELETE` and `OPTIONS`. A `POST` or `PATCH` that failed after the server acted would act twice, so they get one attempt unless `http.Retry.UnsafeMethods` is 1. A host name that did not resolve is not retried either (`http.Retry.NameNotResolved`).

| Console variable | Default | Meaning |
| --- | --- | --- |
| `http.Retry.MaxAttempts` | 3 | Attempts including the first; 1 turns retrying off |
| `http.Retry.BaseDelayMs` | 500 | Wait before the first retry |
| `http.Retry.MaxDelayMs` | 15000 | Longest wait between attempts |
| `http.Retry.JitterPercent` | 25 | Random spread of each wait, either way |
| `http.Retry.MaxRetryAfterMs` | 60000 | Longest `Retry-After` honoured |
| `http.Retry.UnsafeMethods` | 0 | 1 retries `POST` and `PATCH` |
| `http.Retry.NameNotResolved` | 0 | 1 retries an unresolved host |

The wait blocks the calling thread, like the request itself. GameNet's REST client and the remote configuration fetch use it; the crash uploader keeps its own per-endpoint schedule.

## Streaming downloads

`Request` buffers the whole body, which is right for API calls and wrong for game content. `Fetch` and `Download` take `HttpTransferOptions`:

| Field | Default | Meaning |
| --- | --- | --- |
| `headers` | none | Extra request headers |
| `connectTimeoutSeconds` | 10 | Give up connecting after this long |
| `stallTimeoutSeconds` | 30 | Fail when nothing arrives for this long, instead of hanging |
| `maxBytesPerSecond` | 0 (no cap) | Bandwidth cap |
| `cancel` | none | Pointer to an `std::atomic<bool>`; set it to abort |
| `onProgress` | none | Called with bytes received and the total |

```cpp wrap
#include "Http/HttpClient.h"

#include <atomic>
#include <cstdint>

std::atomic<bool> cancel = false;

Mowo::HttpTransferOptions options;
options.cancel = &cancel;
options.maxBytesPerSecond = 4 * 1024 * 1024;
options.onProgress = [](uint64_t received, uint64_t total) {
};

const Mowo::HttpDownloadResult result = Mowo::HttpClient::Download("https://cdn.example.com/dlc/pack1.meaf", "Saved/Downloads/pack1.meaf", options);
```

With `resume` true (the default) and a partial file present, `Download` asks for the rest with a `Range` request. A `206` response appends, a `200` from a server that ignores ranges rewrites the file, and a `416` on a file that is already complete counts as success. Progress counts the bytes already on disk, so a progress bar resumes where it stopped. Error bodies (4xx and 5xx) never reach the file; they come back in `HttpDownloadResult::errorBody`.

## WebSockets

`FHttpWebSocketConnection` is a raw WebSocket over the same libcurl: the upgrade, sending and receiving frames, nothing more. Reassembly, ping answers and message limits are the caller's job; the GameNet module builds its WebSocket client on it. <Source symbol="FHttpWebSocketConnection" />

## Crash uploads

`SentryCrashUploader` uploads crash dumps the crash handler queued. It is configured by the crash-reporting setup rather than called directly; see [Shipping](/docs/shipping/).
