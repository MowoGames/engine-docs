This page takes you from a clean machine to a running Mowo Project Launcher. You install the toolchain the repository pins, clone the engine with Git LFS, check the setup with `mbt doctor`, and build. You do not need CMake or a Vulkan SDK.

## Prerequisites

The repository pins its compiler and SDK versions in `Engine/Config/Toolchains.ini`. A version below the minimum is an error, one between the minimum and the preferred version builds with a warning, and the preferred version is quiet <Source path="Engine/Config/Toolchains.ini" />.

| Requirement | Minimum | Tested with | Notes |
|---|---|---|---|
| .NET SDK | 10 | | `mbt` targets `net10.0` <Source path="Engine/Source/Programs/MowoBuildTool/Directory.Build.props" /> |
| LLVM (clang-cl, lld-link, llvm-lib) | 20.1 | 23 | The compiler on Windows. `mbt` looks in `LLVM_PATH`, the LLVM bundled with Visual Studio, `Program Files\LLVM`, then `PATH` |
| MSVC toolset | 14.38 | 14.51 | Not the compiler: the STL, CRT and libraries clang-cl compiles against. Comes with Visual Studio or the Build Tools and the **Desktop development with C++** workload |
| Windows SDK | 10.0.22621.0 | 10.0.26100.0 | Install it through the Visual Studio Installer |
| Xcode clang (macOS) | 16.0 | 17 | macOS uses Xcode's clang, not upstream LLVM |
| Git and Git LFS | | | Third-party binaries under `Engine/Binaries/ThirdParty` and `Engine/Source/ThirdParty/*/Lib` are LFS-tracked <Source path=".gitattributes" /> |

The shader compiler (DXC) and spirv-cross are vendored in the repository, so you need no separate Vulkan SDK <Source path="Engine/Source/Programs/MowoBuildTool/src/MowoBuildTool.Core/Platform/EnvironmentChecker.cs" />.

<Callout type="warning">
Clone with Git LFS installed. Without it, every third-party library is a small pointer file and the build fails at link time. If you cloned before installing LFS, run `git lfs install` and then `git lfs pull` inside the checkout.
</Callout>

## Install and clone

<Tabs>
<Tab label="Windows">

<Steps>
<Step title="Install Visual Studio and LLVM">
Install Visual Studio or the Build Tools with the **Desktop development with C++** workload; that gives you the MSVC libraries and the Windows SDK. Then install LLVM, or add the Clang component in the Visual Studio Installer.
</Step>
<Step title="Install the .NET 10 SDK and Git LFS">
Install the .NET 10 SDK and Git for Windows, then enable LFS once per user:

```powershell
git lfs install
```
</Step>
<Step title="Clone the engine">
Clone the repository URL you received with your source license:

```powershell
git clone <engine-repo-url> MowoEngine
cd MowoEngine
```
</Step>
</Steps>

</Tab>
<Tab label="macOS">

<Steps>
<Step title="Install the toolchain">
Mowo builds on Apple Silicon (arm64). Install the Xcode Command Line Tools, the .NET 10 SDK and Git LFS:

```bash
xcode-select --install
brew install --cask dotnet-sdk
brew install git-lfs && git lfs install
```
</Step>
<Step title="Clone the engine">

```bash
git clone <engine-repo-url> MowoEngine
cd MowoEngine
```
</Step>
</Steps>

<Callout type="note">
macOS packages are ad-hoc signed and not notarized, so a packaged game does not open on another person's Mac without extra steps <Source path="Engine/Source/Programs/MowoBuildTool/src/MowoBuildTool.Core/Packaging/MacDmgBuilder.cs" />.
</Callout>

</Tab>
<Tab label="Linux">

<Status />

Linux x64 does not build end to end yet. The toolchain and platform layer exist, but the Linux builds of several third-party libraries (SDL3, JoltPhysics, FreeType and others) are not committed, so the engine does not link <Source path="Engine/Documentation/ROADMAP.md" />. Use Windows or macOS for now.

</Tab>
</Tabs>

## Check your environment

Run the doctor from the repository root. Use `mbt.cmd` on Windows and `mbt.sh` on macOS.

<CodeTabs>

```powershell tab="Windows"
.\mbt.cmd doctor
```

```bash tab="macOS"
./mbt.sh doctor
```

</CodeTabs>

The first `mbt` command publishes the build tool as a single `mbt.exe` into `Engine/Source/Programs/MowoBuildTool/publish/` and then runs your command. Later runs reuse it, and the wrapper republishes on its own whenever a build-tool source file is newer than the published binary <Source path="mbt.cmd" />.

The doctor prints a table: the toolchain pins it read, the Visual Studio installations, the MSVC libraries and Windows SDK (on Windows), every LLVM it found, .NET, Git and Git LFS. DXC, spirv-cross, CMake, Ninja and the mobile SDKs are optional rows. It exits `0` when every required tool is present and `1` otherwise, so you can use it as a script gate <Source path="Engine/Source/Programs/MowoBuildTool/src/MowoBuildTool/Commands/DoctorCommand.cs" />.

## Build the engine

Build every module:

<CodeTabs>

```powershell tab="Windows"
.\mbt.cmd build
```

```bash tab="macOS"
./mbt.sh build
```

</CodeTabs>

`build` defaults to the `dev` configuration and the host platform. It also compiles the shaders that modules declare and packs `Shaders.meaf` beside the binaries, so a separate shader step is not needed <Source path="Engine/Source/Programs/MowoBuildTool/src/MowoBuildTool.Core/Build/BuildOrchestrator.cs" />. New `.cpp` files are picked up on the next build; there is no configure step.

Binaries land in one folder per platform and configuration, `Engine/Binaries/<platform>/<config>/`, and file names carry only the name: a `dev` build gives `Engine/Binaries/win-x64/dev/MowoEditor.exe`, a `debug` build `Engine/Binaries/win-x64/debug/MowoEditor.exe`. Each configuration folder has its own `Shaders.meaf` and content archives. Each binary finds the engine root and its archives from its own path, so you can launch it from any working directory.

<Callout type="tip">
`dev` is optimized and keeps assertions, which is what you want for everyday editor work. To step through the engine, also build `-c debug`: it leaves the engine unoptimized. See [Build tool](/docs/build-tool/) for every configuration.
</Callout>

`mbt shaders` recompiles shaders on their own, for example `.\mbt.cmd shaders --watch` to recompile on save <Source path="Engine/Source/Programs/MowoBuildTool/src/MowoBuildTool/Commands/ShadersCommand.cs" />.

## Generate IDE files

`mbt` can write IDE projects for editing and debugging. You still build through `mbt`, or through the generated tasks that call it <Source path="Engine/Source/Programs/MowoBuildTool/src/MowoBuildTool/Commands/GenerateCommand.cs" />.

```powershell
.\mbt.cmd generate vs        # Visual Studio solution (.slnx by default)
.\mbt.cmd generate vscode    # compile_commands.json and tasks.json
.\mbt.cmd generate xcode     # Xcode project (macOS)
```

## Open the launcher

The launcher is part of the default build. Start it from the output folder:

```powershell
& .\Engine\Binaries\win-x64\dev\MowoProjectLauncher.exe
```

The Project Launcher lists your projects and creates new ones. To open an existing project directly, pass its manifest to the editor:

```powershell
& .\Engine\Binaries\win-x64\dev\MowoEditor.exe --project D:\Projects\MyGame\MyGame.mproject
```

[Create a project](/docs/getting-started/create-a-project/) walks through both.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `lld-link: failed to write output … permission denied` | A running editor, game or test process still holds the file. Close it, delete the `.exe`, and build again. |
| An executable exits in under a second with `0xC0000139` or `0xC000012F` | A killed link left zero-filled DLLs that look fresh. Delete them and build again. |
| Link errors for every third-party library | The checkout has LFS pointer files. Run `git lfs pull`. |
| `[mbt] FAILED to publish MowoBuildTool` | The .NET 10 SDK is missing, or a running `mbt.exe`, IDE or antivirus holds the published file. The wrapper refuses to run a stale build tool <Source path="mbt.cmd" />. |
| `mbt doctor` reports `No LLVM satisfies Toolchains.ini` | Install an LLVM at or above the pinned minimum, or point `LLVM_PATH` at one. |
