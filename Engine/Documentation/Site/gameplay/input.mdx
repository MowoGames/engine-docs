Mowo's input system follows Unreal's Enhanced Input. You describe **what** the player can do as input action assets, describe **which hardware** triggers each action in input mapping context assets, and bind gameplay callbacks to actions and trigger events. Gameplay code never polls keys directly.

## How input flows

Each frame, device state passes through the active mapping contexts, their modifiers and triggers, and ends as trigger events your callbacks listen to.

<Flow steps={["Devices", "Active mapping contexts (by priority)", "Binding modifiers", "Action modifiers", "Triggers", "Trigger events", "MPlayerInput callbacks"]} highlight={4} caption="Modifiers transform values; triggers decide when an action fires. Bound callbacks run once per frame from the player controller." />

The pieces:

| Piece | What it is |
| --- | --- |
| Input action (`.inputaction`) | A named action with a value type: `Button`, `Axis1D` or `Axis2D`, plus optional modifiers and triggers <Source symbol="InputActionAsset" /> |
| Input mapping context (`.inputcontext`) | A prioritized set of mappings from a device source to an action, each with its own modifiers and triggers <Source symbol="InputMappingContextAsset" /> |
| `MEnhancedInputSubsystem` | The per-player object you add and remove mapping contexts through. Higher priority contexts are evaluated first. <Source symbol="MEnhancedInputSubsystem" /> |
| `MPlayerInput` | The per-player binding list. `APlayerController` evaluates it every tick. <Source symbol="MPlayerInput" /> |
| `InputActionSystem` | The engine-wide evaluator underneath, with the context stack and player overrides |

Both assets are created from the Content Browser's **Add › New asset › More** menu (**Input Action** and **Input Mapping Context**, also under **New › More** when you right-click an empty area of the asset view), and each opens in its own editor. See [Asset editors](/docs/editor/asset-editors/).

<Screenshot id="gameplay-input-mapping-context-editor" alt="Mowo Editor with IMC_Default.inputcontext open in the Input Mapping Context editor; the mapping list shows Move bound to W, A, S and D with axis and scale columns, Jump bound to Space, and a Hold trigger expanded on one mapping" caption="A mapping context maps device sources to input actions." />

## Trigger events

Every evaluated action reports five events per frame. <Source symbol="InputAction" />

| Event | Meaning |
| --- | --- |
| `Started` | Actuation began this frame |
| `Triggered` | The action fired this frame |
| `Ongoing` | Actuated but not firing yet, for example a hold building up |
| `Completed` | Stopped firing after firing at least once |
| `Canceled` | Actuation ended without ever firing |

## Bind input for a pawn

A pawn binds input in `SetupPlayerInput`, which the player controller calls on possession with a freshly cleared `MPlayerInput`. This character loads the project's default mapping context, activates it, and binds actions by name.

```cpp title="AExplorer.h" nocompile
#pragma once

#include "Game/ACharacter.h"
#include "Game/APlayerController.h"
#include "Game/FControlRebinding.h"
#include "Game/MEnhancedInputSubsystem.h"
#include "Game/MPlayerInput.h"
#include "Input/InputAction.h"
#include "Math/Math.h"

namespace Mowo {

MCLASS()
class AExplorer : public ACharacter {
public:
	MGENERATED_BODY()

	void SetupPlayerInput(MPlayerInput* input) override {
		m_inputContext = FControlRebinding::LoadFromProject("Content/Input/IMC_Default.inputcontext");

		APlayerController* controller = dynamic_cast<APlayerController*>(GetController());

		if (controller && m_inputContext) {
			controller->GetEnhancedInput()->AddMappingContext(m_inputContext.Get(), m_inputContext->GetDefaultPriority());
		}

		input->BindAxis2D("Move", [this](Vec2 value) {
			AddMovementInput(Vec3(value.x, 0.0f, value.y));
		});

		input->BindAction("Jump", ETriggerEvent::Started, [this]() {
			Jump();
		});

		input->BindAction("Crouch", ETriggerEvent::Started, [this]() {
			Crouch();
		});

		input->BindAction("Crouch", ETriggerEvent::Completed, [this]() {
			UnCrouch();
		});
	}
};

}
```

Keep the mapping context alive for as long as it is active: the subsystem only holds a raw pointer to it. `ACharacter` provides the protected `m_inputContext` member for exactly this. <Source symbol="ACharacter" />

`MPlayerInput` has two families of overloads. The ones taking a `const InputActionAsset*` bind to an action asset; the string overloads bind by action name, for code that has not adopted action assets. `BindAxis` and `BindAxis2D` fire every frame with the current value, which is 0 when idle. <Source symbol="MPlayerInput" />

<Callout type="tip">
The engine's character templates load `Content/Input/IMC_Default.inputcontext` first and only build a C++ fallback context when that file is missing. Editing the asset in the editor changes their controls with no code change.
</Callout>

## Modifiers and triggers

Modifiers change an input's value. They can sit on a single mapping, applied to the raw value, or on the action, applied to the combined value. <Source symbol="InputAction" />

| Modifier | Effect |
| --- | --- |
| `Negate` | Flips the sign |
| `Swizzle` | Routes a value to the other 2D axis, or swaps X and Y at action level |
| `DeadZone` | Lower and upper thresholds; radial on 2D action values |
| `Scale` | Multiplies X and Y |
| `Smooth` | Exponential smoothing over time |
| `ResponseCurve` | Exponential response curve (exponent parameter) |
| `FOVScaling` | Multiplies by a field-of-view factor, for aim sensitivity |

Triggers decide when an action fires. With no trigger, the action fires while it is actuated. <Source symbol="InputAction" />

| Trigger | Fires |
| --- | --- |
| `Down` | While actuated (the default) |
| `Pressed` | Only on the frame actuation starts |
| `Released` | Only on the release frame |
| `Hold` | After `duration` seconds held; `oneShot` fires once instead of every frame |
| `Tap` | On release, if the press was short enough |
| `Pulse` | Every `interval` seconds while held |
| `ChordedAction` | Only while another action (`chordAction`) is actuated |
| `HoldAndRelease` | On release, if held at least `duration` seconds |
| `Combo` | When a prerequisite action fired within `interval` seconds |

A `Hold` trigger with `allowToggle` set respects the player's hold-to-toggle accessibility setting (`i.HoldToToggle`): the first press latches the action on and the next releases it. Use it for crouch, sprint or aim, never for a charge. <Source symbol="InputAction" />

## Contexts and priority

- Add a context with `AddMappingContext(imc, priority)` and remove it with `RemoveMappingContext(imc)`. When the controller unpossesses its pawn, it clears all mapping contexts.
- A context that consumes input blocks the contexts below it. <Source symbol="APlayerController" />
- For named contexts defined in project config, use `APlayerController::PushInputContext` and `PopInputContext`. The controller pops whatever it pushed at `EndPlay`. <Source symbol="APlayerController" />

## Player rebinding

A shipped game cannot write its own `Config/` or `Content/` folders, so player choices are stored as overrides in `<project>/Saved/Config/InputUser.mdfb` and re-applied on top of the shipped mappings each time contexts are rebuilt. <Source symbol="InputActionSystem" />

<Steps>
<Step title="Use the shipped rebinding screen">
ArcUI's rebinding screen, backed by `FArcRebindModel`, lists every action of every context, captures a new key or button, reports conflicts, and resets per action or per context. It writes through the player tier. <Source symbol="FArcRebindModel" />
</Step>
<Step title="Or write overrides yourself">
Call `InputActionSystem::SetUserBinding` and then `SaveUserBindings`, as below.
</Step>
<Step title="Reset">
`ClearUserBinding`, `ClearUserBindings` (one context) and `ClearAllUserBindings` restore what the project data supplied. <Source symbol="InputActionSystem" />
</Step>
</Steps>

```cpp title="RebindJump.cpp"
#include "Input/InputAction.h"
#include "Input/InputActionSystem.h"
#include "Input/KeyCode.h"

#include <string>

static bool RebindJumpToSpace(const std::string& contextName) {
	Mowo::InputBinding binding;
	binding.sourceType = Mowo::InputSourceType::Key;
	binding.key = Mowo::KeyCode::Space;

	Mowo::InputActionSystem& actions = Mowo::InputActionSystem::Get();
	actions.SetUserBinding(contextName, "Jump", { binding });

	return actions.SaveUserBindings();
}
```

<Callout type="warning">
`FControlRebinding` edits and saves the mapping context **asset** in `Content/`. That is a development tool, for example a controls editor for your team. Players should go through the player tier above. <Source symbol="FControlRebinding" />
</Callout>

## Mouse settings and debugging

| Console variable | Effect |
| --- | --- |
| `i.MouseSensitivity` | Multiplier on both mouse axes before any modifier (0.05 to 10) |
| `i.MouseInvertY` | Inverts mouse Y |
| `i.HoldToToggle` | Hold-to-toggle for `Hold` triggers marked `allowToggle` |
| `i.DebugOverlay` | Draws a per-action overlay: context, phase, value and trigger events |

## Read input from Visual Scripting

`MInputStatics` gives graphs and C++ the same view of actions without a pawn: `IsActionActive`, `WasActionTriggered`, `WasActionStarted`, `WasActionCompleted`, `GetActionValue` and `GetActionValue2D`, plus `PushContext` and `PopContext`. <Source symbol="MInputStatics" />

## Game input and UI input

The input manager holds an input mode that decides whether device events reach gameplay while game UI is up. <Source symbol="InputManager" />

| Mode | Gameplay receives |
| --- | --- |
| `GameOnly` | Everything; the UI is fed nothing |
| `GameAndUI` (default) | Everything the UI did not consume, so mouse-look does not turn behind an open widget |
| `UIOnly` | Nothing; set it while a pause menu is open |

An event counts as consumed only when a widget handled it, not when a widget merely has focus or is hovered. Key and button releases always reach gameplay, so a key cannot stay stuck down.

## Devices

- **Deadzones** belong to the device, not to each binding: `i.StickDeadzone` (default 0.15) and `i.TriggerDeadzone` (default 0.05) apply to every pad, and `i.Gamepad0.StickDeadzone` to `i.Gamepad3.TriggerDeadzone` override one slot. Project Settings › Engine › Input writes them. Per-binding `DeadZone` modifiers still apply on top.
- **Gamepad slots**: up to four pads, addressed by player slot. The player's slot choice is remembered per device in the same `InputUser.mdfb` file.
- **Rumble**: `InputManager::RumbleGamepad(slot, low, high, ms)` and `RumbleGamepadTriggers`. `i.RumbleScale` scales all rumble.
- **Focus loss** releases every held key and zeroes the axes, so nothing stays held after alt-tab.

### Button prompts

`InputManager::GetLastInputDevice()` reports the family the player last used: keyboard and mouse, or an Xbox, PlayStation, Nintendo, Steam Deck or generic pad. Use it to pick prompt glyphs. `MInputStatics::GetGamepadFamily()` asks the online platform first, and `GetGamepadGlyphPath(button)` returns the platform's glyph image for a button named by Xbox position (`A`, `LB`, `DPadUp`); it is empty without a platform, so keep your own art as a fallback. `ShowOnScreenKeyboard` opens the platform's text keyboard. <Source symbol="MInputStatics" />

## Bindings on disk

Project-wide named contexts live in `Config/Input.ini`, one `[Context Name]` section per context with one `+Action=(...)` line per action. `InputBindingsConfig` reads and writes it. Player overrides go to `Saved/Config/InputUser.mdfb` and win over the project tier. <Source symbol="InputBindingsConfig" />
