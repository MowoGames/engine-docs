A skinned character plays animation through an **Animator** component. The Animator holds the skeleton, the clips and an animation graph, and the animation system turns them into one set of bone matrices per frame for the renderer. This page covers the base pipeline. One-shot animations are on [Montages and notifies](/docs/gameplay/montages-and-notifies/), and IK, retargeting and motion matching on [IK, retargeting and motion matching](/docs/gameplay/ik-and-retargeting/).

## The pose pipeline

Every animated character goes through the same steps each frame. Only the pose source changes: a state machine, a blend space or motion matching.

## The Animator component

`AnimatorComponent` is the per-entity animation state: the skeleton, the clip list, the controller (`controllerPath` names the `.animgraph`), blend layers, montage players, root-motion output and the final `boneMatrices`. <Source symbol="AnimatorComponent" />

On an actor, use `MSkeletalMeshComponent`, which owns the mesh and its animator. Its functions are also Visual Scripting nodes: <Source symbol="MSkeletalMeshComponent" />

| Function | Effect |
| --- | --- |
| `PlayAnimationAsset(clip, loop)`, `PlayAnimation(index, loop)`, `StopAnimation()`, `SetPlayRate(rate)` | Play a single clip without a graph |
| `SetAnimBool`, `SetAnimFloat`, `SetAnimTrigger` | Set a parameter on the animation graph |
| `GetCurrentAnimState()` | The state machine's current state |
| `GetAnimCurveValue(name)` | A curve's value this frame |
| `PlayMontage`, `StopMontage`, `IsMontagePlaying` | See [Montages and notifies](/docs/gameplay/montages-and-notifies/) |

```cpp title="Locomotion.cpp" wrap
#include "Game/MSkeletalMeshComponent.h"

Mowo::MSkeletalMeshComponent* mesh = nullptr;
float speed = 3.2f;
bool grounded = true;

mesh->SetAnimFloat("Speed", speed);
mesh->SetAnimBool("Grounded", grounded);
```

## State machines

The graph's state machine is a set of states joined by transitions. Each state plays a clip, a 1D blend space or a 2D blend space. Transitions test conditions on `bool`, `int`, `float` and `trigger` parameters. A trigger resets once a transition consumes it. <Source symbol="AnimationController::SetTrigger" />

You author the graph in the **Animation Graph** editor. See [Asset editors](/docs/editor/asset-editors/).

<Screenshot id="gameplay-anim-graph-editor" alt="Mowo Editor Animation Graph editor with a locomotion state machine: Idle, Walk, Run and Jump states joined by transition arrows, the Run state selected and its inspector showing the blend space, sync group and transition conditions on Speed" caption="States, transitions and the parameters they test." />

### Transitions

A transition switches state at once and then eases the old on-screen pose into the new one with inertialization, so you do not pay to keep the old clip playing. <Source symbol="FInertializer" />

- **Interruption.** While a blend is still open, only a transition with a strictly higher `priority` can cut in. The cut starts from the current blended pose, so hit reactions and dodges stay smooth.
- **Blend profiles.** A transition can name a blend profile to give each bone its own blend time, for example a faster upper body. <Source symbol="FBlendProfile" />

### Blend spaces

A state can blend between several clips by parameter instead of playing one. <Source symbol="BlendSpace2D" />

- **1D**: two bracketing clips along one axis, such as idle, walk and run by speed.
- **2D**: up to three nearest clips on a grid, such as eight-way strafing by forward and sideways speed. A 2D space takes precedence when both are set.

Blend-space clips are sampled at the same normalized phase, so a short walk and a long run stay foot-synced instead of sliding. Author blend spaces in the **Blend Space** editor.

### Sync groups

States that share a `syncGroup` keep their phase aligned. When a transition enters a state in a group, the new clip starts at the leader's phase instead of at zero, so a walk-to-run change does not pop a foot. Each state's `syncRole` is `Auto`, `Leader` or `Follower`.

## Graph nodes

Beyond the state machine, the `.animgraph` holds a node network that runs after it. Node kinds include `StateMachine`, `Clip`, `BlendByFloat`, `BlendByBool`, `LayeredBlend`, `SavePose` and `UsePose`, `Mirror`, `AimOffset`, `BlendSpacePlayer`, `SequenceEvaluator`, `RandomPlayer`, `ModifyBone`, `CopyBone`, `LookAt`, `TwoBoneIK`, `OrientationWarp`, `StrideWarp`, `SlopeWarp`, `Slot` for montages, the pose-asset nodes `PoseByName`, `PoseBlender` and `PoseDriver`, `TwistCorrective`, and `LinkedLayer` for swapping in another graph. <Source symbol="FAnimGraph" /> Per-entity state lives on the instance, never on the shared asset, so one graph drives any number of characters.

- **Layered blend per bone** blends poses over a base by per-bone weights. `Override` layers replace; `Additive` layers add a delta, in local or mesh space. This is how an upper-body aim layers over locomotion.
- **Mirror tables** pair left and right bones. `AutoGenerate` finds pairs from naming patterns such as `_l` and `_r`; hand-authored pairs are kept.
- **Pose assets** store a handful of tracked bones per pose, for correctives, facial shapes and hand grips.

## Layers

`AnimationLayer` entries on the Animator blend extra clips over the base pose without a graph: `Override` or `Additive` mode, a weight, a speed, a bone mask and optional per-bone weights. <Source symbol="AnimationLayer" />

## Root motion

When `rootMotionEnabled` is set on the Animator, the root bone's movement each frame is extracted instead of played. Set `useRootMotion` on the character's `CharacterMovement` component and that movement drives the capsule: horizontal speed comes from the clip, so turn-in-place, pivots and stops match the animation. See [Character movement](/docs/gameplay/character-movement/). Motion warping bends root motion onto a gameplay target; see [Montages and notifies](/docs/gameplay/montages-and-notifies/).

For root motion in multiplayer, see [Multiplayer](/docs/multiplayer/).

## Performance

The animation system evaluates animators in parallel and can lower the update rate of distant or unseen characters. Skipped frames bank their time, so playback speed stays correct. <Source path="Engine/Source/Runtime/Game/Private/AnimationSystem.cpp" />

| Console variable | Default | Effect |
| --- | --- | --- |
| `a.LOD` | -1 | Update-rate LOD around the focus: -1 on while a focus is set, 0 off, 1 on |
| `a.LODNearRadius`, `a.LODNearInterval` | 30, 4 | Beyond 30 m, sample every 4th frame |
| `a.LODFarRadius`, `a.LODFarInterval` | 120, 16 | Beyond 120 m, sample every 16th frame |
| `a.OffscreenInterval` | 0 | Frame interval for animators not drawn for two updates; 0 keeps them at full rate |
| `a.BudgetMs` | 0 | Per-frame evaluation budget; the lowest-priority animators are deferred. 0 means no budget. |
| `a.BudgetMaxDeferFrames` | 8 | Frames one animator may be deferred in a row |
| `a.LODBoneMask` | 1 | Skips the bones a skeleton LOD removes |

Clips are compressed at import with a per-clip error tolerance and optional per-bone budgets. <Source path="Engine/Source/Runtime/Animation/Public/Animation/AnimationCompression.h" />
