The Outliner and the Details panel sit on the right of the default layout and work as a pair. The Outliner lists every actor in the open scene; the Details panel shows the properties of whatever you select. Both read the same selection as the viewport, so a click in any of the three updates the other two.

<Screenshot id="editor-outliner-details-pair" alt="Right side of the editor: the Outliner listing a scene with a Props folder expanded and one static mesh actor selected, and the Details panel below showing that actor's header, class row and its Transform and MeshRenderer sections." />

## The Outliner

The Outliner shows one row per actor, nested by attachment. Engine-internal entities that no actor backs are not listed, so what you see is what you authored.

### Columns

A header above the tree holds the columns. Drag a column edge to resize it, click a title to sort, and use the gear in the footer to choose which columns appear.

| Column | Shows | Shown by default |
| --- | --- | --- |
| Label | Type icon and the actor's name | Always |
| Type | Friendly type, such as *Directional Light* | Yes |
| Actor Class | The class name, native or Visual Script | No |
| Layer | The actor's layer from Project Settings ▸ Layers | No |
| Tags | The entity tag | No |
| Mobility | Static or Movable | No |
| Pinned, Visibility, Lock | Toggles | Yes |

The column set is defined at. Sorting orders siblings only, so the tree stays a tree.

### Searching

The search box takes plain words and a few prefixes. Terms combine with AND and match case-insensitively.

| Query | Matches |
| --- | --- |
| `crate` | Actors whose name contains *crate* |
| `"wooden crate"` | The name, including the space |
| `type:light` | The Type column |
| `class:AVisualScriptActor` | The actor class |
| `layer:water` | The layer, by name or slot number |
| `tag:prop` | The entity tag |
| `folder:props` | The folder path |
| `-barrel` | Excludes matches |

A filter never flattens the tree: parents of a match stay visible (dimmed), children of a match stay reachable, and pinned rows always show.

### Folders

Folders group top-level actors. They are editor metadata saved with the scene; they do not change transforms or anything at runtime.

<Steps>
<Step title="Create a folder">
Right-click empty space in the Outliner and choose **New Folder**, or select actors and use **Move to Folder ▸ New Folder**.
</Step>
<Step title="Nest it">
Press <Kbd>F2</Kbd> on the folder and type a path such as `Props/Rocks`. The folder moves with everything in it, as one undo step.
</Step>
<Step title="Fill it">
Drag actors onto the folder row.
</Step>
</Steps>

Deleting a folder never deletes actors; they move up to the parent folder.

<Callout type="note">
A folder with no actors in it is kept only in your own editor state, not in the scene file. It becomes part of the scene when the first actor moves into it.
</Callout>

### Selecting and reparenting

Click selects, <Kbd>Ctrl</Kbd>+click toggles, <Kbd>Shift</Kbd>+click selects a range. Drag rows onto another row to attach them; dragging a selected row moves the whole selection as one undo step. The Outliner refuses a drop that would attach an actor under its own child.

Two drags cross into the Content Browser:

- Drag actor rows onto the Content Browser to save them as a prefab (`.prefab`).
- Drag an asset onto an actor row to spawn it attached under that actor.

### Keyboard and row menu

| Key | Action |
| --- | --- |
| <Kbd>F2</Kbd> | Rename |
| <Kbd>Del</Kbd> | Delete |
| <Kbd>Ctrl+C</Kbd> / <Kbd>Ctrl+X</Kbd> / <Kbd>Ctrl+V</Kbd> / <Kbd>Ctrl+D</Kbd> | Copy, cut, paste, duplicate |
| <Kbd>Space</Kbd> | Toggle visibility |
| <Kbd>Enter</Kbd> | Frame the row in the viewport |
| Arrow keys, <Kbd>Home</Kbd>, <Kbd>End</Kbd> | Move through rows; left and right collapse and expand |

The actor clipboard chords are registered at. The row context menu adds **Add Child Actor**, **Add Component**, **Pin to Top**, **Select All of This Class**, **Create Prefab…**, **Move to Folder**, **Layer**, and **Edit … in C++** or **Edit … Script** to jump to the actor's class source.

### Visibility and lock

The eye column hides an actor in the editor. The flag is saved with the scene and is undoable, but it only affects editing: the game and a packaged build draw the actor normally. The lock column stops an actor from being selected in the viewport.

## The Details panel

The Details panel is driven by reflection. Every property a component declares through the reflection macros appears as a row, grouped into one collapsible section per component, with no editor code needed for it. Adding a reflected field to a component is enough to make it editable.

<Flow steps={["Component declares reflected field", "MowoHeaderTool emits TypeDescriptor", "Details builds row and widget", "You edit the value", "One undo entry per edit"]} highlight={2} caption="How a C++ field becomes a Details row." />

### The header

At the top you see the actor's type tile, its editable name and the lock. The line under the name says what the actor is and ends in a link: a mesh actor's opens its mesh (*Edit SM_Crate*), a Visual Scripting actor's opens its `.vscript` class, and a C++ actor's opens its header in your IDE. A C++ class from the project's `Source/` tree wins over an engine class of the same name. When the source cannot be found, the link is greyed out with a tooltip saying why.

Below the header the **Components** box lists the actor, its root component and the components under it, with **Add** in its heading. <Kbd>Shift</Kbd>-click a section header to fold or open every section.

### Adding components

**Add** opens the component picker, the same one the Outliner's row menu and the Actor Editor use. It lists every reflected component the actor does not already have, as **Favourites** (star a row to keep it there), **Recent** (your last picks this session), then by category. Each row has a one-line description. Type to filter by label, type name or category; <Kbd>Up</Kbd>/<Kbd>Down</Kbd> and <Kbd>Enter</Kbd> pick, <Kbd>Esc</Kbd> closes. Adding a component is one undo entry.

### Widgets

The panel picks a widget from the property's type and annotations:

| Property | Row widget |
| --- | --- |
| Vector | Colored X/Y/Z numeric fields |
| Ranged number (`MOWO_RANGE`) | Slider clamped to the range |
| Color (`MOWO_COLOR`) | Swatch that opens a color picker |
| Asset reference (`MOWO_ASSET_TYPE`) | Asset picker filtered to that asset type |
| Layer mask (`MOWO_LAYER_MASK`) | Dropdown of named layers |
| Enum | Combo box or segmented control |
| Array | Expandable list with add, duplicate, remove and drag-reorder |
| Nested struct | Expandable group of the struct's own fields |

The annotations are declared in <Source path="Engine/Source/Runtime/Reflection/Public/Reflection/Reflect.h" />. See the reflection API: [`PropertyInfo`](/docs/api/reflection/propertyinfo/) and [`TypeDescriptor`](/docs/api/reflection/typedescriptor/).

### Units

A number annotated with `MOWO_UNITS` shows its unit after the value and converts where needed <Source path="Engine/Source/Runtime/Reflection/Public/Reflection/Reflect.h" />. A field stored in radians is shown and typed in degrees; you can type `90`, `90deg` or `1.5rad`. A field in meters accepts `150cm`. A suffix from a different dimension is ignored rather than guessed.

### Categories, favorites and search

- `MCATEGORY` groups rows under a mini header inside a component section.
- Right-click any row and choose **Add to Favorites** to echo it in a Favorites section at the top.
- <Kbd>Ctrl+F</Kbd> jumps to the search box. Search reaches inside collapsed arrays and structs.
- The funnel button shows only modified rows: the properties that differ from their defaults.

With the funnel on, each section header gets its own reset arrow that resets every modified property in that component as one undo entry.

<Screenshot id="editor-details-modified-filter" alt="Details panel with the show-only-modified funnel enabled on a point light actor: only Intensity and Light Color rows remain, each with a reset arrow at the right end of the row, and each section header shows its own reset arrow." />

### Resetting and the row menu

A property that differs from its class default has an emphasized label and a reset arrow. Click the arrow to go back to the default. The row's right-click menu offers:

- **Copy** and **Paste** of the value as text.
- **Reset to Default**.
- **Revert to Prefab Value**, on a property that differs from its prefab.
- **Add to Favorites** / **Remove from Favorites**.
- **Copy Internal Name**, the property path used by the scene format.
- For array elements: insert, duplicate and remove.

### Undo for every property

Each committed edit is one entry on the scene's undo history. A slider drag or a scrub is one entry for the whole gesture, not one per frame. If an edit is interrupted before it commits (the selection changes, the scene switches, the color picker closes), the panel commits it anyway, so it is both undoable and counted as unsaved work.

### Editing several actors

With several actors selected, the rows come from the last actor you clicked. Committing a value writes it to every selected actor that has the same component, as one undo entry. Actors without that component are skipped.

When the selection disagrees, number fields go blank and other widgets show a dim dash. The first edit writes the new value to all of them.

<Callout type="note">
Adding, removing or reordering array elements only applies to the primary actor. Element 3 on another actor is a different element, so the panel does not replay structural changes across the selection.
</Callout>

### Custom rows

A few components, such as materials and IK, are drawn by hand through a customization registry. A customization can replace a single row or append its own rows below the reflected ones.

Editor plugins can register their own customizations for a component type through <Source symbol="FEditorExtensionRegistry" />: rows appended under the component's fields, or a block that replaces them entirely. See [Plugins and extensions](/docs/editor/plugins/).

### Locking a Details panel

Open a second Details panel with **Window ▸ New Details**, select an actor, and click the padlock chip in its search row. The locked panel keeps showing that actor while the first panel follows your selection, which is useful for comparing two actors.

### Visual Scripting variables

A placed Visual Scripting actor gets one more section, **Visual Script Variables**, below its components: a row per variable the class marks **Instance Editable**, including those inherited from parent classes. Scalars, vectors, rotations (in degrees) and colours get their usual widgets. An object variable shows a dropdown of the level's actors, or an asset picker when the variable's default names an asset. Container variables are read-only here. A changed value resets to the class default with the reset arrow. See [Visual Scripting](/docs/visual-scripting/).

## The Property Matrix

The Details panel shows one object deeply; the **Property Matrix** shows many objects across chosen properties. Rows are the selection, columns are reflected properties, and every cell is editable in place. Open it with **Window ▸ Property Matrix**; it opens as a tool document whose tab title says what it compares (*Property Matrix · 6 static meshes*).

<Screenshot id="editor-property-matrix" alt="The Property Matrix tool document comparing six selected static mesh actors: the frozen Actor column, MeshRenderer columns including Cast Shadows and a material, one column pinned, and a selection rectangle over four cells of one column." />

Right-click the table to choose the source and columns:

| Source | Rows | Editable |
| --- | --- | --- |
| Selected actors | The viewport and Outliner selection | Every column |
| Content Browser selection | The selected assets | Static mesh settings only: Cast Shadows, Mobility, LOD Group, Nanite and Lightmap Res, written to the mesh's `.mdfmeta` sidecar (not undoable) |

A property becomes a column when its type has a one-line editor: booleans, numbers, strings, asset references, vectors and enums. Structs and arrays are not offered. **Columns…** chooses columns and pins them to the left; **Only components every row has** hides components only part of the selection carries. Rows that lack a component show a dash.

Editing:

- Arrow keys move the cell cursor; <Kbd>Shift</Kbd>+arrows or <Kbd>Shift</Kbd>+click extend a selection rectangle.
- Committing a value in a cell inside the selection writes it down that column into every selected row, as one undo entry. The value never spreads sideways into other columns.
- **Apply to selection** copies the focused cell's value down its column without retyping.
- A value that does not parse is refused.

Click a column header to sort, drag its edge to resize, use **Filter rows…** to narrow by name, **Show only modified** to hide columns where every row agrees, and **Copy as CSV** to put the visible table on the clipboard.

## World Settings

**World Settings** (Window ▸ World Settings, beside Details by default) edits the open level's own settings. Most rows save with the level file, so opening the level elsewhere brings the same setup back; a few rows set console variables. Each row is one undo entry and has a reset arrow when it differs from its default.

| Section | Rows |
| --- | --- |
| World | **Kill Z**: simulated bodies and characters below it are destroyed during play. **Game mode**: the level's override of the project's game mode, used by Play in editor, the packaged game, the server and travel |
| Physics | **Gravity Z**, applied when Play or Simulate starts; **Async physics tick**; **Default volume** |
| Global illumination | Method, fallback, **Bake GI fallback** with progress and Cancel, probe spacing |
| Navigation | **Build on load** (bake when the level opens with no navigation mesh beside it) and **Runtime generation** |
| Debris | Piece budget, maximum spawns per frame, lifetime |
| Advanced | Fog, sky, ambient light, shadows, the AI director, the post-process baseline, streaming collision proxies and time of day |

The post-process baseline is what a camera renders with outside any post-process volume, and the starting point volumes blend on top of: tonemapping, physical camera, auto exposure, bloom, ambient occlusion, reflections, anti-aliasing and colour grading. With **Physical Camera** on, the image is exposed from f-stop, shutter and ISO instead of the exposure value. Lower **Max EV** to keep a dark interior dark. See [Rendering](/docs/rendering/) for what each effect does.

Time-of-day rows appear only when the level has a day-night entity.

## Levels

The **Levels** tab shares the Outliner's area. It lists every open level document, marks the active one, and switches to a level when you click it. For streaming sub-levels and data layers, see [World building](/docs/editor/world-building/).
