Play in editor (PIE) runs your game inside Mowo Editor so you can test a change seconds after making it. Play runs in a copy of the level, so the level you edit is never touched by the game, and stopping returns you to it as it was. The editor offers several ways to play and a multiplayer mode that runs a local server with extra clients.

## The play modes

The chevron on the Play button lists every mode <Source path="Engine/Source/Editor/MowoEditor/Private/Shell/EditorToolbar.cpp" />.

| Mode | Shortcut | What runs |
| --- | --- | --- |
| **Play** | <Kbd>F5</Kbd> | The game in the level viewport, with the project's game mode and a game camera |
| **Play in New Window** | | The game in a separate window, with the editor still visible |
| **Simulate** | <Kbd>Alt+S</Kbd> | The world ticks (physics, AI, animation) but the game mode does not start; you keep the editor camera |
| **Play As Client** | | A multiplayer session; see [Multiplayer sessions](#multiplayer-sessions) |
| **Standalone Game** | | A separate `MowoGame` process, loading the level from disk |

The viewport's context menu also has **Play From Here**, which starts Play with your pawn at the clicked point ([Viewport](/docs/editor/viewport/)).

## What happens when you press Play

<Flow steps={["Copy the level", "Mark the undo history", "Start game mode and camera", "Playing / Paused", "Stop: discard the copy", "Replay live edits onto the level"]} highlight={[0, 4]} caption="Play runs in a copy; Stop discards it." />

1. The editor makes a play copy of the level, including unsaved terrain edits, and marks the undo history <Source path="Engine/Source/Editor/MowoEditor/Private/Core/MEditorEnginePie.cpp" />.
2. Asset hot reload pauses so a file change cannot free data that live actors are using.
3. The game starts. In Play mode the project's game mode spawns the player.

When you stop:

1. The play copy is discarded. The level you edit was never ticked, so it is exactly as before.
2. Edits you made in the editor while playing are replayed onto the level, which is marked unsaved. Your undo history from before Play is kept.
3. Changes captured with **Keep Simulation Changes** are applied as one undo entry.

The Message Log clears its play page each time you press Play.

## Controls while playing

| Shortcut | Action |
| --- | --- |
| <Kbd>Esc</Kbd> | Stop |
| <Kbd>F8</Kbd> | Eject from the game camera to the editor camera, and possess again |
| <Kbd>F10</Kbd> | Advance one frame, while paused |
| <Kbd>Shift+F1</Kbd> | Free the mouse from the game; press again or click the game view to give it back |
| <Kbd>K</Kbd> | Keep Simulation Changes for the selected actors, while simulating or ejected |

The toolbar shows the elapsed time and Pause, Step and Stop buttons while a session runs <Source path="Engine/Source/Editor/MowoEditor/Private/Core/MEditorEngineMenus.cpp" />.

### Mouse capture

In the viewport, the game takes the mouse only if it asks for it, the same way the packaged game does. Click in the viewport to hand the cursor to the game; <Kbd>Shift+F1</Kbd> frees it again. The viewport shows a hint line with these keys while you play <Source path="Engine/Source/Editor/MowoEditor/Private/Panels/ViewportPanel.cpp" />.

### Ejecting and keeping changes

Press <Kbd>F8</Kbd> during Play to get the editor camera back while the game keeps running. You can select actors, inspect their live values in Details and fly around. Press <Kbd>F8</Kbd> again to return to the game camera.

What the game itself did, such as where physics settled a crate, is discarded on Stop. To keep it, select the actors and press <Kbd>K</Kbd> while simulating or ejected <Source path="Engine/Source/Editor/MowoEditor/Private/Core/KeepSimulationChanges.cpp" />. Pressing <Kbd>K</Kbd> again on the same actor replaces its earlier capture. Actors and components spawned during play are skipped.

## Editing during play

Property edits you make while the game runs are recorded and replayed onto the level when you stop, so tuning a value during play keeps it.

<Callout type="note">
Session-only commands and file operations are not replayed. If the game travels to another level or loads a save game, the replay is off for that session and Stop only clears the play-session history.
</Callout>

## Multiplayer sessions

**Play As Client** starts a real networked session on your machine <Source path="Engine/Source/Editor/MowoEditor/Private/Pie/PieMultiplayerSession.cpp" />. Configure it from the Play menu:

| Submenu | Choices |
| --- | --- |
| Multiplayer Clients | How many clients in total |
| Net Mode | **Dedicated Server**: a headless `MowoServer` process loads the level and the viewport connects as the first client. **Listen Server (viewport hosts)**: the editor's own play world hosts and the extra clients connect to it |
| Client Windows | **Inside the Editor**: extra clients draw in floating windows inside the editor. **Separate Windows**: each extra client opens its own OS window |

Extra clients are `MowoGame` processes. With **Inside the Editor**, each client window has a tab strip with the client's number, its net role, frame rate and round-trip time, and a close button <Source path="Engine/Source/Editor/MowoEditor/Private/Pie/PieClientWindows.cpp" />. Click a window to give it keyboard and mouse input; close it to make that client leave.

<Steps>
<Step title="Save the level">
Servers and extra clients load the level from disk, so it must have a file.
</Step>
<Step title="Pick the setup">
Choose the client count, net mode and client windows from the Play menu.
</Step>
<Step title="Start">
Choose **Play As Client**. The editor picks a free loopback UDP port, starts the processes and connects.
</Step>
<Step title="Watch the session">
The **PIE Session** panel lists each child process and streams the server's output <Source path="Engine/Source/Editor/MowoEditor/Private/Panels/PieSessionPanel.cpp" />.
</Step>
</Steps>

While a session runs, the editor watches `Content/`: a changed Visual Scripting class or material is reloaded and every client follows.

The child processes are tied to the editor: on Windows and Linux they end if the editor exits without stopping the session. On macOS they are ended from the editor's own shutdown and crash paths only, so a force-quit editor can leave a server holding the port.

<Callout type="warning">
`MowoServer` (for a dedicated server) and `MowoGame` (for extra clients) must be built and sit next to the editor executable. If one is missing the session does not start and the Message Log says which.
</Callout>

### Network debugging

**Window ▸ Debug ▸ Network Debug** inspects a multiplayer session <Source path="Engine/Source/Editor/MowoEditor/Private/Panels/NetworkDebugPanel.cpp" />. Its tabs are **Overview** (session and transport), **Actors** (replication), **RPCs**, **Bandwidth** (connections and the network simulation) and **Rewind**.

**Rewind** lays the session's recordings on a timeline, one lane per peer with the bytes it moved each frame, and marks frames where a client diverged from the server (desync) or corrected its own prediction <Source path="Engine/Source/Editor/MowoEditor/Private/Panels/NetRewindView.cpp" />. At the cursor frame, a table compares entities between the server and one client, and the viewport draws them. While Play is paused, the frame is put back onto the play world. See [Multiplayer](/docs/multiplayer/) for replication and prediction.

## Standalone Game

**Standalone Game** (also **Build ▸ Launch Standalone Game**) runs `MowoGame` with `--project` and `--scene` pointing at your project and the open level <Source path="Engine/Source/Editor/MowoEditor/Private/Core/MEditorEnginePie.cpp" />. It is the closest thing to a packaged game without cooking. Because it loads the level from disk, the editor asks whether to save first when the level has unsaved changes.

## Troubleshooting

| Symptom | Check |
| --- | --- |
| No player spawns | Simulate does not start the game mode. Use Play, and check the game mode in [World Settings](/docs/editor/outliner-and-details/) or the project settings |
| The game ignores the mouse | Click in the viewport to give it the cursor |
| A fixed error still shows | The Message Log's play page clears on the next Play |
